# Spec: Content search on remote connections (SSH/SMB) V1

Status: implemented
Out of scope: MEGA, find-and-replace on remote, filename-only mode (separate backlog item), search inside remote archives, saved smart folders

## Goal

`StartSearch(mode=content)` works on `ssh://` and `smb://` roots same as it already does for local. Today it hard-errors:

`internal/service/file_service.go:955` `if remote.IsRemote(root) && mode != domain.SearchModeFolders { return fmt.Errorf("content search is not available on remote connections yet") }`

Already shipped, not touched by this spec: remote **go-to** (`SearchTree` / `searchTreeRemote`) and remote **folder-name** search (`searchFoldersRemote`, both in `internal/service/remote_walk.go`). This spec only adds the `content` mode branch.

## Why remotes not "free"

`filesystem.SearchContent` (`internal/filesystem/content_search.go`) is local-fs only: `os.ReadDir`, `os.Open`, `f.Seek(0, io.SeekStart)` to re-read after binary sniff, `runtime.NumCPU()`-sized worker pool doing parallel `os.Open`.

Remote has none of that for free:

- No `os.ReadDir` — traversal goes through `remoteBackend.ListDir`, already wrapped by `walkRemote` (`internal/service/remote_walk.go`), same walker `searchFoldersRemote` already reuses. Its caps (`maxRemoteWalkVisits=2000`, `maxRemoteWalkDepth=8`) and silently-skipped `ListDir` errors are inherited as-is — same behavior remote folder search already ships with.
- No cheap `Seek(0)` guarantee across backends after sniffing for binary — `OpenRead` returns `io.ReadCloser` (`sftp.File` for SSH, `smb2.File` for SMB via `remoteBackend.OpenRead`, added for the duplicate finder: `internal/remote/ssh.go:215`, `internal/remote/smb_fs.go:88`). Don't rely on `Seek` being cheap or present on every backend's reader.
- One round trip per `Open`/`Read` over a shared session — running `runtime.NumCPU()` parallel opens like local content search would hammer a single SSH/SMB session. Precedent already in this repo: duplicate-finder's `hashPath`/`dhashPath` (`internal/service/file_service_dup.go`) call `be.OpenRead` **sequentially**, one file at a time. Do the same here — no worker pool.
- MEGA's `OpenRead` always errors (`internal/remote/mega_hash.go:60`, "MEGA hashes via HashFile instead") — content search on MEGA is not this spec (mirrors backlog wording: "search on remote (SSH and SMB)"). Block MEGA explicitly with a clear error, don't let it fall through to a generic `OpenRead` failure.

## Scope decision: buffer instead of stream-with-seek

Local `scanFileContent` reads an 8 KiB sniff window, seeks back to 0, then `bufio.Scanner`s the rest. For remote, skip the seek dependency entirely:

- Files are already capped at `maxContentFileBytes` (2 MiB) by `Size` from the `FileEntry` the walk already has — no extra stat round trip needed, unlike local `os.ReadDir` + `entry.Info()` which is the same call.
- Read the whole capped file into memory once via `io.ReadAll` (bounded at 2 MiB by the pre-check), binary-sniff the first 8192 bytes of that buffer, then scan lines from the buffer with the same `bufio.Scanner`/line/column/window logic as local (`scanFileContent`'s line-matching body, factored out and reused — do not duplicate the match/preview logic).
- This is safe only because of the existing 2 MiB cap; it must not be applied to duplicate-finder-style whole-file hashing (that path stays streaming, per `specs/duplicate-finder/v1.md`).

## Backend contract

No `remoteBackend` interface changes — `OpenRead` already exists for SSH/SMB.

New, in `internal/service/remote_walk.go` (next to `searchFoldersRemote`):

```
func (s *FileService) searchContentRemote(
    ctx context.Context,
    be remoteBackend,
    root, query, include, exclude string,
    caseSensitive, showHidden bool,
    limit int,
    onHit func(domain.ContentSearchHit),
    onDenied func(path string, err error),
) (truncated bool, err error)
```

- Traversal: `walkRemote`, same as `searchFoldersRemote` — do not write a third walker.
- Per file entry (not dir): `filter.Match(rel)` (reuse `filesystem.NewPathFilter`, same include/exclude semantics as local and as folder search) → skip if `Size == 0 || Size > maxContentFileBytes` → skip if `!filter.MatchDir` on the way down the same way `searchFoldersRemote` prunes directories.
- `be.OpenRead(path)` → on error, call `onDenied(path, err)` and continue (don't abort the walk — matches "skip unreadable, keep going" philosophy of both local content search and remote folder search).
- Extract the line-matching core of `scanFileContent` (binary sniff, needle search, case-fold fallback, `windowLinePreview`) into a shared helper over `[]byte`/`io.Reader` that both local and remote call — do not copy-paste the matching logic into a second implementation.
- Sequential — one `OpenRead` in flight at a time. No goroutines, no worker pool.
- Respects `ctx` cancellation (`walkRemote` already checks `ctx.Err()` per entry).
- `limit` behaves like local: stop and report `truncated = true` once hit count reached.

## Wiring

`internal/service/file_service.go` `StartSearch` guard, replace:

```go
if remote.IsRemote(root) && mode != domain.SearchModeFolders {
    return fmt.Errorf("content search is not available on remote connections yet")
}
```

with a MEGA-only block for content mode:

```go
if mode != domain.SearchModeFolders && remote.IsMEGA(root) {
    return fmt.Errorf("content search is not available on MEGA connections yet")
}
```

(`remote.IsMEGA` already exists — used throughout `backendFor`.)

`runSearch`'s `default:` (content) branch: add a remote arm before the existing local `filesystem.SearchContent` call, mirroring how the `SearchModeFolders` case already branches on `remote.IsRemote(root)`:

```go
default:
    if remote.IsRemote(root) {
        var be remoteBackend
        be, err = s.backendFor(root)
        if err == nil {
            truncated, err = s.searchContentRemote(ctx, be, root, query, include, exclude, caseSensitive, showHidden, limit, onHit, onDenied)
        }
        break
    }
    truncated, err = filesystem.SearchContent(...) // unchanged
```

`onHit`/`onDenied` closures already built above the switch in `runSearch` — reuse them as-is, no payload changes (`domain.SearchHitPayload.Content` already `*ContentSearchHit`).

## Must not

- Parallel `OpenRead` calls (no worker pool) — sequential only, matches `hashPath`/`dhashPath` precedent.
- Rely on `io.ReadCloser.Seek` from `OpenRead` — buffer instead (see scope decision above).
- Duplicate the line-match/preview logic — extract and share with `scanFileContent`.
- Touch `walkRemote`'s caps/behavior — reuse as-is like `searchFoldersRemote` does.
- Enable content search on MEGA.
- Enable find-and-replace on remote (`ReplaceOccurrence`/`ReplaceAllInPaths` stay remote-blocked; separate spec if ever done).
- Reuse duplicate-finder's streaming-hash `OpenRead` pattern for this (no whole-file streaming needed once size-capped).

## Done when

Go:

- [x] `ssh://`/`smb://` root, `mode=content`, query present in a remote file → `search:hit` with correct `line`/`column`/`lineText`
- [x] file over 2 MiB on remote → skipped, not opened (no `OpenRead` call — assert via fake backend call count)
- [x] binary remote file (null byte in first 8192 bytes) → skipped, no hits
- [x] remote `OpenRead` error (permission, gone mid-walk) → `search:denied`, walk continues
- [x] `mode=content` on `mega://` root → sync error, `OpenRead` never called
- [x] cancel mid-search → `search:done` promptly, no goroutine leak (sequential, so trivially true — assert anyway)
- [x] include/exclude globs behave identically to local and to remote folder search (shared `PathFilter`)
- [x] limit truncation reports `truncated` same as local

Frontend:

- [x] content mode enabled (not greyed out) for `ssh://`/`smb://` roots, still disabled for `mega://`
- [x] "not available" banner only shows for MEGA + non-folder mode
- [x] existing remote folder-search and go-to behavior unchanged (regression check)

E2E: none new required — no SSH/SMB fixture server in `e2e/` today; cover via Go unit tests against a fake `remoteBackend` (same style as `internal/remote/openread_test.go`).
