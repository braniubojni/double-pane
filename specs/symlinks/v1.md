# Spec: Symlink and hardlink V1

Status: draft
Out of scope: remote links (`ssh://` `smb://` `mega://`), changing copy so it recreates links, Windows junctions, a path picker that can point outside the machine

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Current behavior

`filesystem.entryFromDirEntry` sets `FileEntry.IsSymlink` from `os.ModeSymlink`. For a symlink it also `os.Stat`s the target and uses the target's `IsDir` and access mode, so a link to a directory opens as a directory. The link's own size is kept when the target is not a directory (`info.Size()` on the link). Search (`SearchFolders`, `SearchContent`) skips symlinks and does not follow them. There is no create-link API. `os.Link` / `os.Symlink` are unused.

## Create

`FileService.CreateSymlink(parent, name, target string) (string, error)`

`FileService.CreateHardlink(parent, name, target string) (string, error)`

Local `parent` only. `name` passes `filesystem.validateName`. `target` is an absolute path after `filesystem.Resolve` for the existence check.

- Symlink: `os.Symlink(target, filepath.Join(parent, name))`. Target may be missing (dangling link is allowed). Target may be a directory.
- Hardlink: `os.Link(target, dest)`. Target must exist and be a regular file. A directory target returns a clear error (`hard link to a directory is not supported`). Cross-device errors from the OS are returned as-is.

Archive parent and trash parent use the same rejects as `Mkdir` (`rejectArchiveWrite`, `rejectTrashDest`).

## Follow toggle

`Settings.FollowSymlinks bool`, JSON `followSymlinks`, default **true** (today's listing).

When true, `ListDir` stays as it is.

When false, a symlink row keeps `IsSymlink: true` and `IsDir: false`, even if the target is a directory. Size and mod-time are the link's own (`Lstat` info), not the target's. Double-click and Enter do not navigate into it. The context menu still has "Open" which then `os.Stat`s and, if the target is a directory, navigates to the target path. That Open is explicit follow. Search behavior does not change (still never follows).

The toggle is in Settings next to `ShowHidden`. Listing reads it the same way the pane reads `showHidden` (the list query arguments). Do not infer it from a `useEffect`.

## UX

Context menu on a local pane background or a local folder row: "New symlink…", "New hardlink…". Two fields in the existing name-dialog style: link name, target path. `data-testid="dialog-symlink"` and `dialog-hardlink`.

Command palette ids `createSymlink`, `createHardlink`. No default function key.

A symlink row already has `IsSymlink`. Show a small "link" mark on the name when `IsSymlink` is true (both follow modes). Do not add a column.

## Tests

## Must not

- Follow symlinks in search or in `DirChildSizes` (those already skip them).
- `ln` via `exec`.
