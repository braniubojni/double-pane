# Spec: Remote passwords in the OS keychain V1

Status: draft
Out of scope: MEGA TOTP seeds, SSH private key material (paths stay on the profile; passphrases for keys may use this store), the folder vault (`specs/folder-vault/v1.md` keeps the vault password in memory only), Linux secret-service libraries beyond what a small `exec` of `secret-tool` can do if the native API needs cgo

Cursor: implement this spec only. Read `internal/AGENTS.md` first.

## Current behavior

`ConnectionProfile` has no password field. `ConnectionService.saveProfiles` writes the profile list as JSON through `storage.DB.SetKV("connections", …)`, which encrypts with the app key in `app.key` next to `app.db`. That is not the OS keychain. Connect always takes the password as an argument (`ConnectProfile`, `ConnectSpec`, `ConnectMEGA`). The dialog keeps it in React state (`addConnectionReducer`). Next launch asks again (`open_password` mode).

`IsAuthError` tells the UI to prompt. SSH also tries the password as a key passphrase (`ConnectProfile` comment).

## Desired

Optional "Save password" on SSH, SMB, and MEGA connect. When set, store the secret in the OS store and reconnect without the dialog until the user removes the profile or chooses "Forget password".

Do not put the secret in `settings.json`, the `connections` kv blob, or `app.key`. The profile gains `HasPassword bool` `json:"hasPassword"` so the UI knows a secret exists without receiving it.

Service account name: `double-pane`. Item key: profile id (`ConnectionProfile.ID`).

- macOS: `security` command, generic password, service `double-pane`, account = profile id. No cgo.
- Windows: `cmdkey` / Credential Manager target `double-pane:<id>`.
- Linux: `secret-tool` (libsecret) with attribute `service` / `account`. If the binary is missing, save returns a clear error and the profile is still saved without a password.

API on `ConnectionService`:

- `SaveProfilePassword(id, password string) error`
- `ForgetProfilePassword(id string) error`
- Connect methods: when `password == ""` and `HasPassword`, read the secret and use it. A stored secret that the server rejects still surfaces `IsAuthError` and the dialog; do not loop.

`RemoveProfile` deletes the keychain item (ignore "not found").

MEGA: store the password only, not the TOTP secret. TOTP stays typed.

## UX

The existing save-connection checkbox stays "save the profile". A second checkbox "Save password in Keychain" `data-testid="conn-save-password"`, default off. Shown for SSH, SMB, and MEGA. Saved profiles with `HasPassword` connect from the menu without `open_password`. A row action "Forget password" clears the item and the flag.

## Tests

Store behind an interface `secretStore` with an in-memory fake in tests: save, connect reads it, forget, remove profile deletes it. Do not call the real `security` binary in `go test`.

## Must not

- Log the password.
- Return the password to the frontend on `ListProfiles`.
- Use `SetKV` for the secret.
