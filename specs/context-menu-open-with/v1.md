# Spec: Context menu closes after Open with V1

Status: implemented
Out of scope: which apps are listed, a custom Open With dialog, changing Copy/Delete/the other context items, Windows/Linux app discovery

Cursor: implement this spec only. Read `frontend/AGENTS.md` first. UI close behavior. No new Go API.

## Problem

Right-click a local file, then left-click **Open with**. The submenu opens and the window stops taking clicks. Escape and a click outside do not dismiss it. The file grid stays blocked until the process is restarted.

Two layers in the current code cause that:

- `FileContextMenu` is a modal MUI `Menu`. `OpenWithMenu` mounts a second `Menu` inside it (`hideBackdrop`, opens on `onMouseEnter` and `onClick`, `stopPropagation` on the row). The second menu is still a modal. Its root eats the outside click, so the parent `onClose` never runs, and `onMouseEnter` opens the submenu again while the pointer is on the row.
- **Other…** calls `FileService.OpenWithPicker` after `onDone()`. On darwin that is a blocking `osascript` “choose application” dialog (`internal/config/openwith_darwin.go`). If it starts while either menu modal is still mounted, the chooser and the webview fight and the app looks hung.

## Close behavior

One context menu. Opening **Open with** shows the app list. Dismissing returns the window to normal use.

- Escape closes the submenu if it is open, and closes the context menu if it is not. A second Escape is not required to get the grid back. After Escape, `file-context-menu` is not in the document and no `.MuiModal-root` from these menus remains.
- A pointer-down outside both the context menu paper and the Open with paper closes both. The click must reach the pane afterward (the next click selects a row).
- Choosing an app or **Other…** closes both menus before `OpenWith` / `OpenWithPicker` is called. `onDone()` (`contextMenuStore.close`) runs first; the service call runs after the menus have committed closed.
- Leaving the **Open with** row closes the submenu. Moving into the submenu keeps it open. `onMouseEnter` must not reopen it in the same turn as an outside click or Escape.
- The submenu must not be a second modal that covers the window. Keep the app list in `OpenWithMenu`. A `Menu` is fine only if its root does not capture outside clicks (`pointer-events: none` on the modal root, `auto` on the paper) and the parent `onClose` still fires. A non-modal `Popper` + `MenuList` is also fine. Do not add a third menu.

Windows stays one row (`ctx-open-with` calls the picker). That row still closes the context menu before `OpenWithPicker`.

## Check

e2e in `e2e/specs/` (follow `e2e/AGENTS.md`). Extend the existing “context menu shows Open with” case in `e2e/specs/ui-polish.spec.ts` or add a sibling test:

- Right-click `note.txt` in the left grid.
- Click `ctx-open-with`.
- Press Escape.
- `file-context-menu` is hidden.
- Click `note.txt` with the left button. The row becomes selected. The menu does not reopen.

Playwright cannot open the native choose-application dialog. On a darwin build, manual check: **Other…** shows the chooser in front of the window, Cancel returns to the file grid with no menu open, and the grid accepts a click.

## Must not

- A second modal left mounted after close.
- Calling `OpenWithPicker` while the context menu is open.
- Listing a different set of apps, or scanning `/Applications` again on every mouse move.
- `document` or `window` in the menu. The submenu is `NestedMenuItem`.

## Done when

Open with can be opened and then dismissed with Escape or an outside click, and the pane accepts the next click. **Other…** does not run until the menu is gone.
