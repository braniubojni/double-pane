# Spec: Archive and extract on SSH and SMB V1

Status: draft
Out of scope: MEGA, archive browse of a remote zip (the pane still does not open `ssh://…/a.zip` as a virtual folder), changing empty-file creation

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Current behavior

Empty file: `FileService.CreateFile` already works for remote parents. It checks `Exists`, then `remoteBackend.WriteTextFile(path, "")`. The toolbar and context menu call it (`onMkfile`) with no remote guard. Leave that path alone.

Archive: `FileService.Archive` returns `archive is not supported for remote paths yet` when any source or the dest is remote (`file_service_archive.go` / `file_service.go`). `Extract` and `ExtractBatch` return `extract is not supported for remote paths yet`. Local archive uses `filesystem.Archive` / `Extract` (`zip`, `tar.gz`, … in `CreateFormats`) and emits `transfer:progress` without `transfer:done` (the frontend `useArchiveExtract` owns the status-bar row).

The toolbar buttons `btn-archive` and extract are not disabled for remote paths; the user gets the error after confirm.

## Desired

SSH and SMB can create an archive and extract one. MEGA still returns the current error.

Do the pack locally, then upload, so `filesystem.Archive` / `Extract` stay the implementation:

- **Archive:** download remote sources to a temp dir (same cleanup rules as a transfer temp: `os.TempDir()/double-pane-arch-<jobID>`, removed on success, error, and cancel). Run `filesystem.Archive` into that temp. Upload the archive file to `destPath`. If dest is local and sources are remote, skip the upload and archive straight into the local dest after download. If sources are local and dest is remote, archive to temp (or a local sibling only when dest is local) and upload. Mixed schemes in `sources` stay an error.
- **Extract:** if the archive path is remote, download it to temp, `filesystem.Extract` into a temp dir, upload the extracted tree to `destDir` when dest is remote, or extract straight into a local dest. `ExtractBatch` uses the same rule per item.
- Password zip stays `filesystem.Archive`'s existing zip password argument.
- Progress: reuse `transfer:progress` for the download, pack, and upload phases under the same `jobID`. Still no `transfer:done` (the frontend already closes the row).
- Cancel deletes the temp dir and a partial remote dest file.

Formats stay `ListArchiveCreateFormats`. No new format.

## UX

No new dialog. `ArchiveDialog` works when the pane is `ssh://` or `smb://`. Dest path is the other pane when that is what the dialog already uses for local. A MEGA pane still shows the backend error.

`data-testid` values stay `btn-archive`, `dialog-archive`.

## Tests

Classifier or helper test with a fake backend:

- remote source + local dest produces a zip whose entries match the downloaded names
- MEGA path still errors
- temp dir removed after success
- `CreateFile` on a remote parent is not modified (no new test required if the branch is untouched)

## Must not

- Shell out to `zip` or `tar`.
- Implement remote archive virtual folders in this spec.
