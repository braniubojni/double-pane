# Spec: SSH key auth in the connection dialog V1

Status: draft
Out of scope: generating a new key pair, writing `~/.ssh/config`, agent forwarding to a remote `ssh` from the pane, SMB

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Current behavior

Auth is implemented in `remote.Manager.buildAuthMethods`: password, `IdentityFiles` on `remote.Spec`, and ssh-agent (`golang.org/x/crypto/ssh/agent`). `remote.EnrichSpec` / `ConnectFromConfig` merge `IdentityFile` from `~/.ssh/config`. The native OpenSSH dial (`openssh.go`) also passes `-i` for those paths. Empty password tries keys and the agent first (`Connect` comment).

The dialog does not pick a key. "Add SSH connection" is a spec string plus password. "Connect from SSH config" lists `SSHConfigHost` (alias, host, user, port, `identityFiles`) but the user cannot add a key path on the free-form form. On failure the password field is labeled "Password or key passphrase" and the helper text tells the user to set `IdentityFile` in `~/.ssh/config` (`ConnectionDialog.tsx`). Agent forwarding (`ForwardAgent`) is not a session flag.

`ConnectionProfile.IdentityFiles` is already persisted when it came from config. A hand-added profile usually has none.

## Desired

On the add-SSH form and on the password retry form:

- A key file field. Browse is the existing path completion (`usePathCompletions`) plus a path the user can type. Empty means "agent and config only", which is today.
- The chosen path is prepended to `Spec.IdentityFiles` before `Connect` / `EnrichSpec` (same order as `mergeIdentityFiles`: explicit first, config files after).
- Checkbox "Use ssh-agent" default **on**. When off, `buildAuthMethods` skips the agent for that dial. Default on preserves today's behavior.
- Checkbox "Forward agent" default **off**. When on, the session requests agent forwarding on the SSH client (`ssh.Client` / OpenSSH `-A` for the `openssh.go` dial). Forwarding applies to later remote terminal or remote `ssh` from that session only if the app already opens channels on that client; if the file manager never opens a shell channel, still set the flag on the client config so a later terminal spec can use it. Do not forward by default.

Passphrase: the existing password field remains the key passphrase when a key path is set and the key is encrypted. Do not add a second secret field.

Saved profile stores `IdentityFiles` (already on the struct) and two new bools:

```go
UseAgent     bool `json:"useAgent"`
ForwardAgent bool `json:"forwardAgent"`
```

`UseAgent` missing in old JSON means true. `ForwardAgent` missing means false.

## UX

`data-testid="ssh-identity-file"`, `ssh-use-agent`, `ssh-forward-agent` on the add-SSH dialog. Config-host flow shows the host's identity files as read-only text and still allows one extra path.

## Tests

`buildAuthMethods` (or its test neighbor in `internal/remote`):

- identity path set → public key method before password
- `UseAgent` false → agent method absent even when `SSH_AUTH_SOCK` is set (inject the agent dial)
- empty identity and agent on → same methods as today

Profile JSON without the new fields unmarshals to use-agent true, forward false.

## Must not

- Copy private key bytes into SQLite. Store the path only.
- Turn on agent forwarding unless the checkbox is set.
