# Spec: system tray icon, on by default, toggle in Settings V1

Status: draft
Out of scope: minimize-to-tray-on-window-close (`Mac.ApplicationShouldTerminateAfterLastWindowClosed` stays `true`, unchanged — closing the window still quits the app, same as today), "start at login", tray icon reflecting app state (job progress/update-available badges), Linux-DE-specific fallback UI (Wails already degrades silently where no tray/notification area exists)

## Goal

App gets a system tray icon (`app.SystemTray`, `wails/v3/pkg/application`) with a small menu (Show window, Quit). On by default. Settings gets one toggle, "Show tray icon", default on — turning it off hides the tray icon, turning it back on shows it again, no restart needed either way.

## API (researched: https://v3.wails.io/features/menus/systray/)

`app.SystemTray.New()` returns `*application.SystemTray`, works the same shape on Windows/macOS/Linux:

```go
systray := app.SystemTray.New()
systray.SetIcon(iconBytes)          // go:embed'd PNG
menu := app.NewMenu()
menu.Add("Show Double Pane").OnClick(func(ctx *application.Context) { win.Show(); win.Focus() })
menu.AddSeparator()
menu.Add("Quit").OnClick(func(ctx *application.Context) { app.Quit() })
systray.SetMenu(menu)
```

Relevant for this spec specifically:

- `systray.Show()` / `systray.Hide()` — toggle visibility live, no re-create needed. **No `IsVisible()` getter** — the "on/off" state we care about is `Settings.ShowTrayIcon`, tracked ourselves; we never need to read it back from the tray object.
- There is **no "don't create the tray at all" mode** — `New()` is a one-time call at startup regardless of the setting. "Off" means "created, then `Hide()`'d," not "never created." (Matters for the default-off-and-never-touched case: still call `New()`, just call `Hide()` right after if `Settings.ShowTrayIcon` is false at boot.)
- `systray.Destroy()` on shutdown — resource cleanup, goes in the existing `app.OnShutdown` callback (`main.go:97-103`) next to the other teardown calls already there.
- Icon requirements differ per platform (Windows 16x16/32x32, macOS 18x18-22x22 — template style recommended for dark-mode, Linux 22x22-48x48) — see Files expected, a real asset gap, not code.

New file `tray.go` (package `main`, next to `window.go`, same style — small free functions taking the services they need, not a new struct):

```go
//go:embed assets/tray-icon.png
var trayIcon []byte

func setupSystemTray(app *application.App, win *application.WebviewWindow, show bool) *application.SystemTray {
    systray := app.SystemTray.New()
    systray.SetIcon(trayIcon)
    systray.SetLabel("Double Pane")

    menu := app.NewMenu()
    menu.Add("Show Double Pane").OnClick(func(ctx *application.Context) {
        win.Show()
        win.Focus()
    })
    menu.AddSeparator()
    menu.Add("Quit").OnClick(func(ctx *application.Context) {
        app.Quit()
    })
    systray.SetMenu(menu)

    if !show {
        systray.Hide()
    }
    return systray
}
```

`internal/service/settings_service.go` — `SettingsService` gets one more post-construction wire, same pattern as `AttachUpdateApp`/`fileSvc.SetApp` already used for `updateSvc`/`fileSvc`/`termSvc` in `main.go`:

```go
type SettingsService struct {
    db  *storage.DB
    cfg *config.Store
    onTrayChanged func(bool) // optional; nil until main wires it
}

func (s *SettingsService) SetTraySync(fn func(bool)) {
    s.onTrayChanged = fn
}
```

`SaveSettings` (`internal/service/settings_service.go:52-58`) calls it after a successful write:

```go
func (s *SettingsService) SaveSettings(settings domain.Settings) error {
    settings = normalizeSettingsForSave(settings)
    data, err := json.Marshal(settings)
    if err != nil {
        return err
    }
    if err := s.db.SetKV(kvSettings, data); err != nil {
        return err
    }
    if s.onTrayChanged != nil {
        s.onTrayChanged(settings.ShowTrayIcon)
    }
    return nil
}
```

Called unconditionally (not diffed against the previous value) — `Show()`/`Hide()` are idempotent, and diffing buys nothing here.

```go
settingsSvc.SetTraySync(func(show bool) {

```

```tsx
  <FormControlLabel
    control={
      <Switch
```

## Must not

- Add minimize/hide-to-tray-on-window-close behavior — not asked for, and it's a bigger decision (changes what the red/×  button does, needs its own confirmation UX for "still running in tray"). `Mac.ApplicationShouldTerminateAfterLastWindowClosed` stays `true`.
- Skip creating the tray when the setting is off at boot — `New()` always runs once; "off" is `Hide()`, not "never call `New()`." Needed so flipping the setting back on later doesn't require a restart.
- Add "start at login," badge/state icons, or any tray content beyond Show + Quit — not asked for, scope creep on a "have a tray icon" request.
- Try to detect/report Linux tray-unsupported environments — Wails already degrades silently (icon just doesn't render); no code needed, no error to surface.
- Diff old vs new `ShowTrayIcon` before calling `Show()`/`Hide()` in the save hook — both are idempotent, the extra state tracking buys nothing.
