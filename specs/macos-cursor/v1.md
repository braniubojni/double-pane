# Spec: Visible mouse pointer on macOS 27 V1

Status: draft
Out of scope: a custom cursor image, Windows/Linux cursor changes, changing click-to-select or keyboard focus, restyling the file grid

Cursor: implement this spec only. Read root `AGENTS.md` and `frontend/AGENTS.md` first. The symptom is the **mouse pointer** (the arrow), not a text caret and not row selection.

## Problem

On macOS 27 (darwin 27) the pointer is missing while it is inside the window. The app is a Wails v3 WKWebView (`main.go`, `application.WebviewWindowOptions`). Two different bugs look similar. Check which one you have before editing.

1. **Stuck drag class.** `frontend/src/app/theme.tsx` sets `cursor: grabbing !important` on `body.gfm-file-dragging *`, and `no-drop` when `gfm-drop-invalid` is also set. If those classes stay after a drop, every cursor in the window is wrong. That cursor is still visible.
2. **Invisible arrow.** No drag class, and the system pointer is hidden over the webview. This is the WKWebView bug on recent macOS: CSS `cursor: auto` / `default` never reaches AppKit, so the pointer disappears until it leaves the window. An I-beam in a text field can still appear, because that cursor is set explicitly.

Confirm on a darwin 27 build (`wails3 dev` or a packaged `.app`). In the webview console, with the pointer over the file grid and no drag in progress, `document.body.className` must not contain `gfm-file-dragging`. If it does, fix the drag cleanup and stop. If it does not, ship the fix below.

## Fix

### CSS baseline

In `MuiCssBaseline` (`frontend/src/app/theme.tsx`), set `cursor: default` on `html`, `body`, and `#root`. Do not set it on `*`. Buttons, links, text fields, the grab cursor on column resize, and the drag rules must keep their own cursors.

The drag rules stay more specific than the baseline:

- `body.gfm-file-dragging, body.gfm-file-dragging *` → `grabbing !important`
- `body.gfm-file-dragging.gfm-drop-invalid, …` → `no-drop !important`

### Darwin nudge

CSS alone often does not show the arrow in this webview. Add a darwin-only nudge:

- On mouse move inside our window, if the element under the pointer computes to `auto` or `default`, set the AppKit arrow cursor (`NSCursor.arrow`).
- If the computed cursor is anything else (`text`, `pointer`, `grab`, `grabbing`, `no-drop`, `row-resize`, …), do nothing. AppKit must not cover those.
- Run it only for `runtime.GOOS == "darwin"`. No Windows or Linux file.
- Look at the Wails v3 window already created in `main.go` and use its native handle / existing ObjC bridge. Do not add a new CGo dependency and do not vendor a second webview.
- Register the monitor when the window is created, and remove it on shutdown. A move handler that outlives the window is a leak.

If the Wails build we depend on has no way to see the `NSWindow` without a private fork, stop and say so in the PR. Do not guess selectors.

### Drag class

While you are in `theme.tsx`, only change the baseline cursor. If you found a stuck `gfm-file-dragging`, fix the pointer-up / window-blur path that adds it (file-pane drag code). Pointer-up outside the window must clear both `gfm-file-dragging` and `gfm-drop-invalid`.

## Tests

No screenshot test and no Playwright assertion. e2e runs in server mode, not WKWebView, and cannot see the OS pointer.

Go: if the "should we set the arrow?" decision is a pure function of the CSS cursor name, table-test that function (`default`/`auto` → yes, `text`/`pointer`/`grabbing`/`no-drop`/`row-resize` → no).

## Manual check (darwin 27)

- Arrow over the file grid, toolbar, and empty pane.
- I-beam in the path field and in any dialog text field.
- Pointer on buttons and menu items.
- Drag a row: grabbing; hover a file (not a folder): no-drop; drop or release outside the window: arrow returns.
- Windows/Linux: no cursor change. Don't restyle them.

## Must not

- `cursor: none` anywhere.
- A global `* { cursor: default !important }`.
- A custom `.cur` / `.png` cursor.
- Hide the pointer on non-darwin.

## Done when

On darwin 27 the arrow is visible over the grid, text fields still show an I-beam, and file drag still shows grabbing / no-drop.
