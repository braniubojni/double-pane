# Spec: Duplicate finder V2 (similar images + optional OCR)

Depends on: V1 exact SHA-256 job, events, dialog states, exclude, MEGA temp download.
Do not change V1 exact-hash behavior when extra matchers are off.

## Goal

Same Find duplicates dialog. User can also find:

- photos that look the same after resize/recompress/crop-light
- (optional) images that share the same OCR text

Review still ends in Merge → existing `FileService.Delete`.

## Honest split

| Matcher           | What it catches                     | What it misses                         |
| ----------------- | ----------------------------------- | -------------------------------------- |
| V1 SHA-256        | bit-identical files                 | resized / exported JPEG                |
| V2 visual (dHash) | same picture, different encode/size | different crop/angle, different people |
| V2 OCR            | same screenshot/doc text            | normal photos with no text             |

The “90% similar photos” slider is **visual Hamming similarity**, not OCR confidence. OCR uses its own text similarity.

## Setup (extends V1)

Keep: root, hidden, min size, exclude, exact SHA-256 always on.

Add:

- [ ] Similar images — default ON for this spec once shipped; default OFF if you want zero surprise on MEGA.
      Recommendation: default **ON** locally, **OFF** on `mega://` until estimate is confirmed (see MEGA cost).
- Similarity: slider 70–100, default **90**. Meaning: keep a visual pair if similarity >= slider.
- [ ] OCR text — default OFF. Disabled + hint if `tesseract` is not on PATH (`OCRAvailable() bool`).
- OCR language: `eng` default. No language pack UI in V2.

Estimate must return extra fields:

- `imageCount`
- `etaExactSeconds` (V1)
- `etaVisualSeconds` (decode + dHash; MEGA = download ALL images)
- `etaOcrSeconds` (only if OCR on; much larger)
- `megaDownloadBytes` = exact size-tie bytes + (if visual or OCR) bytes of all images

Show the MEGA warning using `megaDownloadBytes`, not V1 size-tie-only bytes.

Start disabled until estimate succeeds.

## MEGA / remote cost (do not hide)

V1 only downloads size-ties.
Visual or OCR **must read image pixels**, so every matching image in the tree is downloaded (still via existing MEGA temp-hash/download helper).

- Similar images ON, OCR OFF: download all `jpg/jpeg/png/webp/gif` under root (and `heic` only if decode is already possible; otherwise skip + count skipped).
- OCR ON: same set, plus tesseract per image.
- Exact hash still runs first on size-ties so bit-identical files stay in Exact groups and are not duplicated in Visual groups.

Cancel must abort download, decode, and tesseract.

## Running

Reuse `dup:*` events. Extend progress:

- `phase`: `walk | exact | visual | ocr`
- `doneImages`, `totalImages` when in visual/ocr

Do not invent a second job type. One `jobId`.

## Review

Three sections, never mixed into one undifferentiated list:

1. Exact (V1 groups) — label “Identical”
2. Visual — label “Similar photos (~N%)” with the pair’s similarity
3. OCR — label “Similar text” with a short snippet (first 80 chars)

A file that is in an Exact group must not also appear in Visual/OCR groups.

Default keep = first path sorted, same as V1.
Merge is still one `Delete` of all checked rows across sections.

Preview V2:

- local images: existing Open
- remote images: no decode-in-webview required. Optional later.

## Visual matcher (required for V2.1)

- Decode with stdlib `image` + jpeg/png/gif + `golang.org/x/image/webp`.
- Compute **64-bit difference hash (dHash)**. Pure Go. No CGo. No OpenCV.
- Similarity = `(64 - hamming(a,b)) / 64 * 100`.
- Pair files with similarity >= slider. Union-find into groups (A~~B and B~~C ⇒ one group).
- Only compare images. Non-images ignored by this matcher.
- Cap: skip files larger than 50 MiB for visual/OCR (exact hash still considers them).

Suggested lib: small dHash implementation in-repo under `internal/imghash/` (do not pull an abandoned phash module if it fights go.mod). Tests with two fixtures: same image resized, and two unrelated images.

## OCR matcher (V2.2 — optional)

- Invoke system binary `tesseract <file> stdout -l eng` with timeout (30s/image).
- No `gosseract`, no CGo, no WASM Tesseract. Wails already has GTK CGO pain.
- If binary missing: checkbox disabled; `OCRAvailable() false`.
- Normalize text: lower, collapse whitespace, strip < 3 char tokens.
- Pair if Jaccard(token sets) >= slider/100 **or** one text contains the other and both have ≥ 20 tokens.
- Empty OCR text → skip, not a group.
- Never run OCR on files already in an Exact group.

## Must not

- Cloud OCR APIs
- CGo Tesseract / OpenCV
- Name-fuzzy / EXIF grouping in V2.1–V2.2 (V2.3 later)
- Change V1 when both extra checkboxes are off
- Hand-edit bindings
- Auto-delete
- Second concurrent dup job

## Done when

V2.1:

- [ ] Two JPEGs of the same photo at different sizes → one Visual group at 90%
- [ ] Two different photos → no Visual group
- [ ] Exact pair still only in Exact
- [ ] MEGA estimate bytes include all images when Similar is on
- [ ] Cancel stops a visual pass
- [ ] Slider 90 default wired

V2.2:

- [ ] tesseract missing → checkbox off
- [ ] two screenshots same text → OCR group
- [ ] photo with no text → no OCR group
- [ ] timeout skip, not fatal
