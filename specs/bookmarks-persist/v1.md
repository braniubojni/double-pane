# Spec: Bookmarks survive an app update V1

Status: implemented
Out of scope: a second bookmark database, exporting bookmarks to JSON, iCloud sync, moving `app.db` into the `.app` bundle or into Documents, encrypting the `bookmarks` table, changing settings/shortcuts encryption

Cursor: implement this spec only. Read root `AGENTS.md` and `internal/AGENTS.md` first. Do not add a new store until the checks below say the current file is actually the wrong place.

## What is already true

Bookmarks are rows in SQLite, not files inside the app bundle.

- `storage.Open(domain.AppName)` in `main.go` opens `os.UserConfigDir()/double-pane/app.db`.
- `domain.AppName` is `"double-pane"` (`internal/domain/models.go`).
- macOS path: `~/Library/Application Support/double-pane/app.db`. Linux: `$XDG_CONFIG_HOME/double-pane` or `~/.config/double-pane`. Windows: `%AppData%/double-pane`.
- The `bookmarks` table is plaintext (`internal/storage/storage.go`). `app.key` encrypts the `kv` table (settings, shortcuts) only. A new key does not delete bookmark rows.
- `BookmarkService.List/Add/Remove` is the only writer. `migrate()` is `CREATE TABLE IF NOT EXISTS`. Nothing in-repo runs `DELETE FROM bookmarks` except `Remove`.

So "save bookmarks in the user folder" is already the design. An update that only replaces the `.app` or `bin/double-pane` must not touch that directory. If bookmarks still disappear, the process is opening a different file, failing the read and hiding it, or exiting before SQLite commits.

## Confirm which failure it is

Do this before writing a migration. On a machine that lost bookmarks, look at the file, don't guess.

1. Log the resolved directory once at startup (`db.Dir()`). Info level, one line: `config dir: …`.
2. Check these directories for an `app.db` whose `bookmarks` table is non-empty:
   - `UserConfigDir()/double-pane`
   - `UserConfigDir()/Double Pane` (Wails `Name` in `main.go` is `"Double Pane"`; an older build may have used it)
   - next to the executable, and `Contents/Resources` inside the `.app` (only if a file is actually there)
3. Check the UI. `useBookmarks` in `frontend/src/entities/file/queries.ts` and `BookmarksSelect` default to `[]`. A failed `List()` looks the same as an empty table. If the query errors, show that error on the bookmarks control. Do not render an empty list over an error.

Decision:

| What you find | What to ship |
| ------------- | ------------ |
| Rows still in `double-pane/app.db`, UI got an error | Surface the error. Fix the open/list failure. No migration. |
| Rows in a legacy directory, canonical `app.db` empty or missing | One-time import below. |
| Canonical file has an empty `bookmarks` table and no legacy file | Do not invent rows. Ship the shutdown checkpoint and the reopen test so the next update cannot drop a committed insert. |

## Shutdown checkpoint

`main.go` closes the db in `app.OnShutdown`. The updater's Restart & Apply (`UpdateService.CheckAndInstall` → Wails `app.Updater`) may replace the process without that hook. Confirm in the installed Wails module whether Restart runs `OnShutdown`. If it does not:

- Add a pre-restart hook the updater actually calls, and from that hook `PRAGMA wal_checkpoint(TRUNCATE)` then `db.Close()`.
- Keep the existing `OnShutdown` close. Closing twice must be safe (`DB.Close` already nil-checks).
- Do not checkpoint on every bookmark write.

`modernc.org/sqlite` is already opened with WAL (`storage.OpenPath`). Leave WAL on.

## One-time import

Only if a legacy `app.db` from the table above has bookmark rows and the canonical db does not (count is 0).

- Open the legacy file read-only. Copy `id, name, path, sort_order, created_at` in one transaction.
- Skip a row whose `path` already exists (`UNIQUE`).
- Do not delete or rename the legacy file.
- Run once per process start, guarded by a `kv` flag `bookmarksImportedFrom` so a later empty canonical db is not re-filled from a stale legacy file the user already cleaned up. Set the flag even when the legacy file had zero rows, after you have looked.
- If the legacy file is missing, set nothing and continue.

No new table. No change to `Add` / `Remove`.

## UI

`BookmarksSelect`: when `useBookmarks` is in error, show the error text in the existing control (caption or disabled field). Placeholder "Bookmarks" stays for the empty, successful list.

Do not add a settings page for the db path in this spec. Startup log is enough.

## Tests

`internal/storage` (no GTK, no Wails):

- Insert two bookmarks, `Close`, `OpenPath` the same file, `ListBookmarks` returns both paths.
- Import: legacy db with two rows, canonical db empty, import copies them, second import does not duplicate, legacy file still exists.
- Import: canonical already has a path, legacy has the same path, result is one row.
- `Close` on a nil or already-closed db returns nil.

Frontend: no new e2e unless the error state is easy to trigger. Do not point e2e at the real `~/Library/Application Support`.

## Must not

- Store `app.db` inside the bundle, next to the binary, or under a path that changes when the `.app` is replaced.
- Drop or recreate the canonical db because it "looks old".
- Encrypt bookmarks.
- Hand-edit `frontend/bindings/**`. This spec adds no Wails method if import stays inside `storage.Open` / service startup. If you do add a method, regenerate bindings and leave them unstaged.

## Done when

- A bookmark inserted, process closed, process opened on the same `UserConfigDir` is still listed.
- Restart path checkpoints and closes the db if `OnShutdown` does not run.
- Legacy directory is imported only when the canonical table is empty, and only once.
- A failed `List()` is visible in the bookmarks control.
