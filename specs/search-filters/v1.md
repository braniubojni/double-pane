# Spec: Filter search hits by size, date, and type V1

Status: draft
Depends on: file-name mode if it lands first (`specs/search-filename/v1.md`). This spec is valid without it: filters apply to content and folder hits that exist today.
Out of scope: smart folders, a query language (`size:>10mb` typed into the search box), indexing

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Current behavior

`StartSearch(jobID, root, query, mode, include, exclude string, caseSensitive, showHidden bool, limit int)` filters only by name or text, include/exclude globs (`NewPathFilter`), and hidden. `domain.SearchHit` has `Name`, `Path`, `IsDir`, `RelPath` — no size or mod-time. `ContentSearchHit` has line fields and no size. The dialog (`SearchForm`) has query, replace, include, exclude, and the mode radios.

Hits that fail a size test still count toward `limit` today, because the test does not exist. Filters in this spec run **before** the limit so a tight size range does not truncate on irrelevant files.

## Fields

Add optional filters to `domain.SearchPrefs` (persisted with the other search prefs):

```go
MinSize   int64  `json:"minSize"`             // bytes, 0 = no min
MaxSize   int64  `json:"maxSize"`             // bytes, 0 = no max
ModifiedAfter  int64 `json:"modifiedAfter"`   // unix ms, 0 = no bound
ModifiedBefore int64 `json:"modifiedBefore"`  // unix ms, 0 = no bound
Type      string `json:"type"`                // "" | "file" | "dir" | "image" | "text" | "archive"
```

`StartSearch` gains these parameters at the end. Wails bindings regen; do not commit `frontend/bindings/**`.

`SearchHit` gains `Size int64` and `ModTime int64` (unix ms), filled for file-name and folder hits from the walk's `FileInfo`. Content hits do not grow those fields; the walker already has the file info and applies the filter before `OnHit`.

## Rules

- Size: file only. A directory row passes the size filter always (directory size is not computed here). `MinSize` inclusive, `MaxSize` inclusive. `MaxSize > 0 && MaxSize < MinSize` is a search error, not zero hits.
- Date: `ModTime` of the file or directory, inclusive, compared in unix milliseconds. No EXIF.
- Type, applied to the candidate before it can be a hit:
  - `""` no extra type test
  - `file` — not a directory (folder mode then returns nothing; that is correct)
  - `dir` — directories only (content mode returns nothing)
  - `image` — extension `jpg`, `jpeg`, `png`, `gif`, `webp` (same set as `imghash` visual names; HEIC is not image here)
  - `text` — the content-search binary sniff (no NUL in the first bytes it already uses). Do not add a second sniffer.
  - `archive` — browsable suffix list in `filesystem/archive_browse.go` (`.zip`, `.tar`, `.tar.gz`, …)
- Content mode: a file that fails size, date, or type is not opened for the text scan.
- Remote walks (`searchFoldersRemote`, `searchContentRemote`) get the same tests from `domain.FileEntry.Size` and `ModTime`. MEGA content search stays unavailable.

## UX

A "Filters" disclosure under the include/exclude row in `SearchForm`. `data-testid="search-filters"`.

- Min and max size as text fields in KB (UI converts to bytes; empty = 0).
- Two date fields (native `input type="date"` via MUI `TextField` `type="date"`). Empty = unbounded. The day is local start or end of that date.
- Type select: Any, Files, Folders, Images, Text, Archives.

Changing a filter does not auto-run. Search still runs from the existing button / Enter.

## Tests

Local temp dir, content or file walk:

- 10 byte file excluded by `MinSize: 100`
- file with old mod-time excluded by `ModifiedAfter`
- `notes.txt` excluded by type `image`
- a passing file is inside the limit count; a filtered file is not

## Must not

- A post-filter in React that hides rows the backend already counted as hits.
- Recursive directory size.
