# Spec: SFTP pause, resume, cancel, and live progress V1

Status: draft
Out of scope: SMB, MEGA, local copies, reconnect-after-drop, resume after the app quits, a new progress event channel, changing worker counts, cross-host copy (`cross-host copy not supported` stays)

Cursor: implement this spec only. Read `internal/AGENTS.md` first. SSH/SFTP only: upload, download, and same-host copy (`internal/remote/ssh.go`, `internal/remote/transfer.go`).

## What already works

Do not rebuild it.

- `Copy` / `Move` go through `FileService.runTransfer` and emit `transfer:progress` / `transfer:done`.
- Same-host SFTP copy uses a worker pool (`newXferPool`, `filesystem.WorkerCount(IONetwork, …)`).
- The status bar (`TransferStatusSegment`) already shows bytes, per-file rows, job cancel, and per-file cancel.
- Job cancel (`CancelJob`) aborts the context. On cancel, same-host copy deletes partial dests (`CopyWithinCtx` removes `created` when `context.Canceled`). Keep that.
- `CancelTransferFile` is documented as local-only. Remote jobs ignore it today (`file_service.go`).

## Progress bug

`copyRemoteFile` (`ssh.go`) calls `copyUnwrapped` with `destSize: nil`. In `copyUnwrapped`, a nil `destSize` adds `knownSize` on the first flush, so a large within-host copy jumps to done before the bytes move.

Upload and download already pass a `destSize` func. Within-host copy must too: stat the remote dest and report that size. Intermediate ticks have to move. A one-file copy of a known size must not emit `bytesDone == bytesTotal` until the dest stat says so.

`io.Copy` stays. The comment in `copyUnwrapped` is the reason: `*sftp.File` `WriteTo` / `ReadFrom` uses concurrent packets. Do not replace it with a manual buffer loop.

## Pause and resume

In-process only. Same SSH connection, same job id. Pause does not close the files and does not delete the dest.

- `FileService.PauseTransfer(jobID)` and `ResumeTransfer(jobID)`.
- Unknown id or a job that is not an SFTP transfer: return an error the UI can show. Pausing a local/SMB/MEGA job is an error, not a silent no-op.
- Implement pause as a gate inside `Read` of a reader wrapped around the SFTP/local source, so `io.Copy` blocks in `Read` and the files stay open. Resume lets `Read` continue.
- The gate is per job. Every worker in that job blocks. New files are not started while paused (the pool's enqueue waits on the same gate or on `ctx`).
- Cancel while paused still cancels: close src/dst via the existing `context.AfterFunc`, delete partial dests, emit `transfer:done`.
- Pause does not emit `transfer:done`.
- Add `Paused bool` to `domain.TransferProgressPayload`. On pause, emit one progress event with the current byte counts and `paused: true`. On resume, emit one with `paused: false`. Do not keep ticking while paused.
- If the connection dies while paused, resume returns that error and the job finishes as failed. Do not dial again.

Quitting the app drops the pause. Next launch does not resume a half-written remote file. Do not write an offset journal.

## Per-file cancel on SFTP

`CancelTransferFile(jobID, path)` must abort one SFTP source and leave the other sources in the job running.

- Key the existing per-file cancel by the source path string the job was given (`ssh://…`), not `filesystem.Resolve`. `Resolve` is for local paths and will fail or mis-key remote ones.
- Cancelling one file closes that file's src and dst, deletes that file's partial dest, and marks that row `canceled` in `TransferFileProgress`. Other workers continue.
- Job-wide cancel still deletes every partial dest for that job.

## UI

`TransferStatusSegment`:

- Pause and Resume on the job row, next to the existing cancel. `data-testid="btn-transfer-pause"` and `btn-transfer-resume"`.
- When `paused` is true, the bar does not animate, the caption says Paused, Resume is shown, Pause is hidden.
- Per-file cancel stays. It must call `CancelTransferFile` with the remote source path and actually stop that file (today the button is already there; the backend ignores it).

`useTransferEvents` / `transferStore.updateProgress`: store `paused` on the op. Selector must stay a stable snapshot (boolean or the existing op object). Do not build a new array inside the selector.

No new event name. Same `transfer:progress`.

## Tests

Go, no real SSH server required:

- Reader wrapper: `Read` blocks while paused, returns bytes after resume, returns `context.Canceled` if the context is cancelled while paused.
- `copyUnwrapped` with a `destSize` that grows: at least one progress callback has `0 < done < total` for a payload bigger than one tick. A nil `destSize` test can stay as documentation of the old jump, or be deleted once no caller passes nil. `copyRemoteFile` must pass non-nil.
- Per-file cancel records the remote path key without `filepath` cleaning that drops the `ssh://` prefix.

Do not require an sshd in CI.

## Must not

- Change SMB or MEGA transfer code in this spec.
- Delete dests on pause.
- Replace `io.Copy` in `copyUnwrapped`.
- A second job id for the resumed copy.
- Hand-edit bindings. Regenerate and leave `frontend/bindings/**` unstaged.

## Done when

- A large same-host SFTP copy reports intermediate bytes.
- Pause freezes bytes and keeps the partial dest; Resume continues the same job; Cancel while paused deletes partials.
- Cancelling one file in a multi-file SFTP job stops that file only.
- The status bar shows Paused and Resume.
