# Spec: Folder compare and one-way sync V1

Status: draft
Out of scope: content merge (three-way), remote (`ssh://` `smb://` `mega://`), archives, `trash://`, vaults, byte-identical sync of symlinks, a background watcher

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first. This is not `GitService` / `GitFileDiff`. Git status stays a column on a repo listing.

## Goal

Compare the active pane's directory with the other pane's directory. Show files that differ. Optionally copy the chosen side's files onto the other side (one-way). Two-way means "copy each side's unique files to the other side" in one job, not a merge of two edited copies of the same file.

## Current behavior

There is no compare. `FileService.Copy` / `Move` copy a selection. `filesystem.ListDir` returns `domain.FileEntry` (`Name`, `Size`, `ModTime` unix ms, `IsDir`, `IsSymlink`). `GitFileDiff` is HEAD vs working tree for one local file.

## Compare

`FileService.CompareDirs(left, right string) (domain.DirCompare, error)`

Both paths must be local directories (`filesystem.Resolve`). Remote, archive, or trash: return an error the dialog can show. Do not follow directory symlinks (same rule as `filesystem.SearchFolders`, which skips `os.ModeSymlink`). A symlink file is a row, compared by link path text (`os.Readlink`), not by the target's bytes.

Walk one level of children first (the names the panes show). A subdirectory that exists on both sides is one row of kind `dir`, plus nested file rows only when the user expands it (a second `CompareDirs` on that pair). Do not walk the whole tree in the first call.

```go
type DirCompare struct {
    Left  string
    Right string
    Rows  []DirCompareRow
}

type DirCompareRow struct {
    Name   string
    Rel    string // slash-separated, relative to the compared dirs
    Kind   string // only-left | only-right | differ | same | dir
    Left   *FileEntry
    Right  *FileEntry
}
```

`differ` when both are regular files and (`Size` differs or `ModTime` differs by more than 2 seconds). Do not hash in the compare call. A "Compare contents" action on one `differ` row calls the existing SHA-256 `filesystem.HashFile` for those two paths and returns equal or not. Same size and mod-time is `same` without hashing.

## Sync

`FileService.SyncDirs(jobID, src, dst string, rels []string) error`

`rels` are relative paths the user checked. Copy each from `src` to `dst` through the existing local copy (`transferLocal` / `filesystem` copy), emitting `transfer:progress` and `transfer:done` like `Copy`. Overwrite an existing dest file. Do not delete dest files that are absent from src (that is not this spec). Cancel via `CancelJob` deletes partial dests the way local copy already does.

Two-way in the UI is two `SyncDirs` calls: left→right for `only-left`, right→left for `only-right`. `differ` is never auto-copied in two-way. The user picks a side per row or skips it.

## UX

Command palette and `config.ShortcutCatalog` id `compareDirs`. No default function key (F3 is quick view, F4 edit, F5 refresh). Toolbar button `data-testid="btn-compare-dirs"` enabled when both panes are local directories.

Dialog `data-testid="dialog-compare"`:

- Table: name, kind, left size, right size.
- Filter chips: different, only left, only right. `same` rows hidden until a "Show identical" switch.
- Buttons: "Copy to right", "Copy to left", "Copy unique both ways". Disabled when the selection has nothing that action can do.
- `differ` rows have "Hash both". Result is one line in the row, not a second dialog.

## Tests

`go test` with two temp dirs:

- file only on the left → `only-left`
- same size and mod-time → `same`
- size differs → `differ`
- symlink dir on one side is not descended
- `SyncDirs` copies the checked relative path and leaves an unchecked extra dest file in place

## Must not

- Hash every file during `CompareDirs`.
- Delete extras on the destination.
- Compare remote paths by downloading them.
