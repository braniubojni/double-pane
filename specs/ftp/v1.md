# Spec: FTP V1

Status: draft
Out of scope: FTPS (implicit TLS on 990), SFTP (that is `ssh://`), FXP (server-to-server), MEGA-style sharing, browsing FTP inside archives, active-mode port juggling beyond PASV

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Current behavior

Remote schemes are `ssh://`, `smb://`, `mega://` (`remote.IsRemote`, `remote.SchemeOf`, `remote.ParseLocation`). `FileService.backendFor` sends SSH to `remote.Manager`, SMB to `SMBManager`, MEGA to `MEGAManager`. The `remoteBackend` interface is `ListDir`, completions, `Exists`, copy/move within, download, upload, `Delete`, `Rename`, `Mkdir`, read/write text, `DirChildSizesCtx`, `OpenRead`.

`ConnectionService` stores profiles in the encrypted SQLite kv key `connections` (`domain.ConnectionProfile`, `Protocol` `ssh` | `smb` | `mega`). A profile whose protocol is anything else fails connect with `protocol %s not implemented yet`.

There is no FTP client.

## Desired

Scheme `ftp://user@host:port/path`. Default port **21**. `remote.IsFTP`, and `IsRemote` / `SchemeOf` include it. `ParseLocation` accepts the same user-host-port-path shape as SSH.

New `remote.FTPManager` implementing the operations `remoteBackend` needs. `FileService` holds it beside `smb` and `mega` and `backendFor` returns it for `ftp://`. `ConnectionService` connect/save/list/disconnect follow the SMB methods (`connectSMB`, `upsertSMBProfile`): protocol `"ftp"`, password passed into `Connect` and **not** written on the profile (passwords stay a separate spec).

Transfer: upload, download, and same-host copy/move use the existing `FileService` transfer classification (`transferUpload`, `transferDownload`, `transferRemoteWithin`) once `SchemeOf` returns `"ftp"`. Cross-scheme (FTP↔SSH) stays `cross-protocol copy not supported` until that spec says otherwise.

Control connection is plain FTP. Data connection is PASV only. One session per `user@host:port`, same map style as `SMBManager.sessions`.

Operations:

- `ListDir` → `domain.FileEntry` (`Name`, `Path` as `ftp://…`, `IsDir`, `Size`, `ModTime`, `Ext`). Hidden names (leading `.`) follow `showHidden`.
- `Mkdir`, `Rename` (basename only, `validateName` rules), `Delete` (recursive for directories).
- `ReadTextFile` / `WriteTextFile` for the editor, with the same size/binary guards the SSH text methods use.
- `OpenRead` for checksum and duplicate hashing.
- `CreateFile` already calls `WriteTextFile` with `""` for any remote backend. No extra create API.

Auth: username and password. Anonymous is user `anonymous` and an empty password, not a special mode. Connect failure returns an error the connection dialog already shows.

## UX

Connections menu: "FTP…" next to SSH and SMB. Dialog mode `add_ftp` in `addConnectionReducer` / `ConnectionDialog`, fields host, user, port (default 21), password, save checkbox. `data-testid="menu-conn-ftp"` and `dialog` mode title "Add FTP connection".

Pane paths, tabs, and the cloud mark (`isRemotePath`) treat `ftp://` as remote. `isRemotePath` in the frontend must include the scheme.

## Tests

Parse table: `ftp://a@h:21/x` → user, host, port, path. `IsRemote` true. `SchemeOf` is `ftp`.

Dial tests use a local `net.Listen` stub that speaks the few commands we send (`USER`, `PASS`, `PASV`, `LIST`, `RETR`, `STOR`, `MKD`, `DELE`) or skip with a fixture if a stub is too much for V1 — prefer a small stub in `internal/remote/ftp_test.go` over a live server.

## Must not

- Route `ftp://` through `remote.Manager` (SSH).
- Store the password in the profile JSON.
- Shell out to `ftp` or `curl`.
