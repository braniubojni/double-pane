# Spec: Batch rename V1

Status: draft
Out of scope: renaming across directories, EXIF/metadata tokens, a rename journal, remote undo, touching `trash://` or archive members

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Goal

Rename many selected files in the active pane with one pattern. The user sees every old→new name before anything is written.

## Current behavior

`FileService.Rename(oldPath, newName string)` renames one basename. It rejects archive members (`rejectInsideArchive`) and trash (`rejectTrashDest`). Remote paths go to `remoteBackend.Rename` (SSH, SMB, MEGA). The UI is one `NameDialog` (`onRename` in `useFileOpDialogs.ts`). `filesystem.validateName` rejects empty, `.`, `..`, and names containing `/` or `\`.

There is no pattern, counter, or regex rename.

## API

`FileService.PreviewBatchRename(paths []string, spec domain.BatchRename) ([]domain.BatchRenameRow, error)`

`FileService.ApplyBatchRename(rows []domain.BatchRenameRow) error`

```go
type BatchRename struct {
    Mode      string // pattern | regex
    Pattern   string // pattern mode: tokens below
    Find      string // regex mode: Go regexp, RE2
    Replace   string // regex mode: $1 or ${1}
    Counter   int    // pattern mode start, default 1
    Pad       int    // pattern mode zero-pad width, default 0
    CaseFold  bool   // regex only
}

type BatchRenameRow struct {
    Path    string
    OldName string
    NewName string
    Error   string // set in the preview; Apply skips rows with Error
}
```

Pattern tokens, replaced in the basename only (extension stays unless the token string includes it):

- `[N]` original name without extension
- `[E]` extension without the dot, empty if none
- `[C]` counter, starting at `Counter`, incrementing in the order of `paths`
- `[C:3]` same as `[C]` with pad width 3 (overrides `Pad` for that token)

Example: `[N]_[C:2].[E]` on `a.txt`, `b.txt` with counter 1 → `a_01.txt`, `b_02.txt`.

Regex runs on the full basename. Invalid regex: `Preview` returns an error, no rows. A replacement that fails `validateName`, collides with another new name in the set, or collides with an existing sibling that is not itself being renamed: that row's `Error` is set, `NewName` may still be shown.

`Apply` calls `Rename` once per clean row, in order. On the first `Rename` error, stop and return that error plus how many earlier rows already changed. Do not try to roll back. Do not add a transaction.

Remote rows use the same `Rename` (already remote-aware). Mixed local and remote in one batch: error, apply nothing.

## UX

Selection of 2+ items. Context menu and command palette id `batchRename`. Dialog `data-testid="dialog-batch-rename"`:

- Radio: Pattern / Regex.
- Pattern fields or find/replace fields.
- Live table of old name and new name. Rows with `Error` show the message and are unchecked.
- Apply is disabled when every row has an error or none are checked.

One item still uses the existing `NameDialog`. Do not replace that path.

## Tests

Table for `PreviewBatchRename` (no disk):

- `[N]_[C:2].[E]` counter 1
- regex `^(.*)\.txt$` → `$1.bak`
- two rows producing the same new name → both `Error`
- `../x` as a product of the pattern → `Error`
- invalid regex → error

`Apply` on a temp dir renames two files and leaves a third.

## Must not

- A second rename implementation that skips `validateName`.
- Writing files. Rename only.
