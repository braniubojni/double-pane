# Spec: Smart folders V1

Status: draft
Out of scope: live updates while the pane is open, Spotlight/FSEvents, remote-only indexing, storing a smart folder as a `Bookmark` row

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Goal

Save the current Find-in-files query and reopen it later as a named smart folder. Opening it runs that search again. It is not a directory the pane can list.

## Current behavior

Bookmarks are directories. `domain.Bookmark` is `ID`, `Name`, `Path`, `SortOrder`, `CreatedAt`. SQLite table `bookmarks` in `internal/storage/storage.go`. The toolbar `BookmarksSelect` navigates a pane to `Path`.

`SearchPrefs` (query, replace, include, exclude, mode, flags) is one global blob, not a list of saved searches. `search_history` stores recent strings per field, not a folder.

## Storage

New table in the same `app.db` migration (`storage.migrate`), next to `bookmarks`:

```sql
CREATE TABLE IF NOT EXISTS smart_folders (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    root TEXT NOT NULL,
    prefs TEXT NOT NULL, -- JSON domain.SearchPrefs plus filter fields if specs/search-filters landed
    created_at TEXT NOT NULL
);
```

`BookmarkService` stays bookmarks. New methods on `SettingsService` or a small `SmartFolderService` registered in `main.go` — prefer methods on `BookmarkService` only if the UI is the bookmark dropdown. The dropdown is the right home: a second list under the paths, not a new toolbar icon.

```go
type SmartFolder struct {
    ID        int64
    Name      string
    Root      string
    Prefs     SearchPrefs
    CreatedAt string
}
```

`ListSmartFolders`, `AddSmartFolder`, `RemoveSmartFolder`. Name required, unique by case-insensitive name. Root is the directory the search ran in (the active pane path at save time), stored as given (`ssh://` allowed). Prefs JSON uses the existing search-prefs shape. Do not put the password or replace history into this row beyond what `SearchPrefs` already stores.

## UX

Search dialog, when there is a query: button "Save as smart folder" `data-testid="btn-save-smart-folder"`. Asks for a name (default: the query, trimmed, max 80 runes).

`BookmarksSelect` section "Smart folders" after local and remote bookmarks. Choosing one does **not** call pane navigate. It opens the search dialog, writes that root and prefs into the search store, and starts the search (`StartSearch`) against `Root`. The pane path stays where it was.

Delete from the same dropdown row (same pattern as bookmark remove). No rename in V1.

If root is missing or the remote session is down, the search shows the existing `search:error` path. Do not delete the smart folder.

## Tests

`storage` or service test: add, list, remove round-trip; duplicate name errors; prefs JSON keeps `mode`.

## Must not

- A virtual `smart://` path in `ListDir`.
- Overloading `bookmarks.path` with a JSON blob.
