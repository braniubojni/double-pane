# Spec: Disk usage treemap V1

Status: draft
Out of scope: remote (`ssh://`, `smb://`, `mega://`), archives, `trash://`, vault decrypt, delete or move from the map, color by file extension, a treemap library, a third pane, replacing the file grid, allocated-block sizes, inode dedup

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Goal

Show one local folder as a squarified treemap (WinDirStat-style rectangles sized by byte size). The map is that folder, not the volume. Opening the volume root is just opening that folder. The status-bar free-space line stays as it is.

## Current behavior

`filesystem.DiskUsage` (`internal/filesystem/disk_usage_unix.go`, `disk_usage_windows.go`) is `statfs` / Windows volume capacity: `domain.DiskUsage` `Total`, `Free`, `Used`. `useDiskUsage` draws "Free: …" on `StatusBar.tsx`. That number is the volume, not a folder.

`filesystem.DirChildSizesCtx` (`internal/filesystem/sizes.go`) sums immediate child directories for the grid size column. It skips symlink children, sums `FileInfo.Size()` of files only (a directory's own metadata size is not added), and records unreadable subtrees on `domain.DirSizes.Denied`. `FileService.DirChildSizes` runs that walk on a `NewJobID` context. There is no tree, no files in the result, and no picture.

Nothing draws a treemap.

## Size rules

Same walk as `dirSizeCtx`. Do not invent a second definition of "size".

- `os.Lstat`. Do not follow symlinks. A symlink child is omitted (not a node, 0 bytes). Do not add the link's own length.
- A regular file's size is `FileInfo.Size()` (logical size). Do not read the file. Do not use `Stat_t` blocks, `DiskUsage`, or allocated size. APFS clones and sparse files can make the sum larger than the volume's `Used`. Leave that mismatch alone.
- A directory's `Size` is the sum of included descendant file sizes. Do not add the directory inode's own `Size()`.
- Hard links: count each directory entry. Do not dedupe inodes. Same as `filepath.Walk` in `dirSizeCtx`.
- Include dotfiles and dot-directories always. Ignore `settings.showHidden`. A disk map that hides `.git` is wrong.
- Do not skip `node_modules`, caches, or `.git`.
- Unreadable directories: skip the subtree, keep any bytes already summed, append the path to `denied`. Same idea as `dirSizeCtx` (`os.IsPermission` → skip, other walk errors → skip that node and continue). Do not fail the whole scan.
- A directory that `vault.Detect` says is a vault: do not descend and do not decrypt. Count its on-disk size with `dirSizeCtx` (ciphertext and manifest) and keep it as a leaf directory. If the scan root itself is a vault, return an error and emit nothing.
- Cancel: stop the walk, emit `usage:done` with `error` set and `tree` omitted. Do not emit a partial tree.

`maxDepth` default **4**. Depth 1 is an immediate child of the scan root. A directory at depth `maxDepth` is a leaf: `Size` includes everything under it, `Kids` is empty. `maxDepth <= 0` means 4. Deeper bytes are in the ancestor `Size`, not dropped.

After the depth-limited tree exists, collapse at every directory: a child whose `Size * 100 < rootTotal` (under 1% of the scan root) is removed and summed into one sibling:

- `name`: `Other`
- `path`: `""`
- `isDir`: false
- `size`: the sum

Omit `Other` when that sum is 0. A small directory disappears into `Other` and cannot be drilled; the file pane still opens it. Sort remaining children by `size` descending, then `name` ascending. `Other` sorts by its size with the rest.

Then `json.Marshal` the done payload. If it is over 2 MiB (`2 << 20`), clear `Kids` on the deepest directories (they stay as sized leaves) and marshal again, repeating until it fits or no directory has kids. Set `truncated` when any kids were dropped this way. Collapse first so the cap is a backstop.

## API

`FileService.TreeUsage(jobID, root string, maxDepth int) error`

Same shape as `StartSearch`: return as soon as the walk is scheduled. `jobID` comes from `NewJobID`. Empty `jobID` is an error. `jobCtx` + `CancelJob` + `FinishJob` in a defer, same as `runSearch`.

Refuse before starting a goroutine (return the error, emit nothing):

- empty or not a directory (`filesystem.Resolve`, then `os.Stat`)
- `filesystem.IsTrashPath`
- `filesystem.IsArchivePath`
- `remote.IsRemote`
- `vault.Detect(root)` is true

Walk in `internal/filesystem` (new file next to `sizes.go`, same package, so it can call `dirSizeCtx`). The service only checks the root, takes the job context, and emits.

Events, via the existing `FileService.emit`:

```go
type UsageNode struct {
    Name  string      `json:"name"`
    Path  string      `json:"path"`
    Size  int64       `json:"size"`
    IsDir bool        `json:"isDir"`
    Kids  []UsageNode `json:"kids,omitempty"`
}

// usage:progress — at most every 100ms, same throttle as duplicate-finder progress.
type UsageProgress struct {
    JobID   string `json:"jobId"`
    Current string `json:"current"`
    Files   int    `json:"files"`
    Bytes   int64  `json:"bytes"`
}

// usage:done — once, when the walk finishes, is canceled, or fails after start.
type UsageDone struct {
    JobID       string     `json:"jobId"`
    Root        string     `json:"root"`
    Total       int64      `json:"total"`
    Files       int        `json:"files"`
    Truncated   bool       `json:"truncated"`
    Denied      []string   `json:"denied"`      // at most 100 paths
    DeniedCount int        `json:"deniedCount"` // full count, may be > len(Denied)
    Error       string     `json:"error,omitempty"`
    Tree        *UsageNode `json:"tree,omitempty"`
}
```

`Tree` is the root folder (its `Kids` are depth 1). `Total == Tree.Size`. `Files` is the number of regular files included. On cancel or a mid-walk failure, `Error` is set, `Tree` is nil, `Total` is 0. Canceled `Error` contains `context.Canceled`'s text.

Do not emit one event per file. Do not stream a chunk per directory.

Regenerate Wails bindings. Do not commit `frontend/bindings/**`.

## UX

Entry points:

- Actions menu item "Disk usage map", `data-testid="btn-treemap"`, next to "Find duplicates…". Disabled when the active path is empty, remote, trash, or an archive (`isRemotePath`, `isTrashPath`, `isLocalArchivePath`). No new toolbar icon. `ToolbarBar` is already a full row; analysis actions live in this menu.
- Command palette id `treeUsage`. Label "Disk usage map". No default binding. Add it to `ShortcutCatalog` in `internal/config/config.go` with an empty default, the way an action with no key still appears in the palette. `runShortcutAction` opens the dialog. Do not add it to `FILE_OPS_IDS`.

Dialog, not a pane. Lazy-load from `FileManagerPage` the same way as `QuickViewDialog`:

```tsx
const TreemapDialog = lazy(() =>
  import('../../widgets/disk-treemap/TreemapDialog').then((m) => ({ default: m.TreemapDialog })),
);
```

`Suspense` fallback `null`. Do not render it while the editor workspace is open.

`data-testid="dialog-treemap"`. MUI `Dialog`, `fullWidth`, `maxWidth="lg"`, content about 70vh. Title is `Disk usage — {base name}`. One line under the title: `formatSize(total, false)` once `usage:done` has a tree, plus ` · N files`.

Zustand (`features/disk-treemap/`): `open`, the scan `root` captured when the dialog opens (active pane path at that moment), `jobId`, and a session cache of done payloads keyed by root. Opening the dialog calls `NewJobID` then `TreeUsage`. Switching the active pane while the dialog is open does not change the scan. Escape and the backdrop close the dialog and call `CancelJob` if a scan is in flight. Closing does not change the pane path or selection.

While scanning: indeterminate `LinearProgress`, the basename of `usage:progress.current`, and bytes so far via `formatSize`. Button "Cancel" (`data-testid="btn-treemap-cancel"`) calls `CancelJob`. Subscribe with `Events.On` in one effect (`useTreeUsageEvents`), the same pattern as `useTransferEvents`. Ignore events whose `jobId` is not the current job.

Layout is a squarified treemap in `widgets/disk-treemap/layout.ts` (pure function, no DOM). Sort is already done by Go; the function lays out the given order. Algorithm (Bruls / Huizing / van Wijk, a few dozen lines): fill the rectangle by rows along the shorter side; add the next node to the current row while the worst aspect ratio does not get worse; then commit the row and repeat. Input is `Tree.Kids` plus the content box size. Output is `{ path, name, size, isDir, x, y, w, h, colorIndex }`. `colorIndex` is the top-level child's index; nested rects copy the ancestor's index. `Other` (`path === ""`) has no color index.

Paint one absolutely positioned `Box` per rect inside a `position: relative` container. 1px gap by insetting each rect (the dialog background shows through). Color is a fixed cycle of theme tokens, by `colorIndex`: `primary.main`, `secondary.main`, `success.main`, `warning.main`, `info.main`, `primary.dark`, `secondary.dark`, `success.dark`. `Other` uses `text.disabled`. Label the name when `w >= 48` and `h >= 16`, ellipsis, `theme.palette.getContrastText`. No canvas library, no SVG dependency.

Hover: MUI `Tooltip` with name, `formatSize(size, false)`, and percent of `Total` (one decimal under 10%, otherwise an integer). No `document` or `window` listeners.

Click a directory (`isDir && path`): cancel the in-flight job, set that path as the scan root, run `TreeUsage` again. A leaf directory (depth cap or a vault leaf) is still clickable, so the user can go deeper. Breadcrumb of roots visited in this dialog session, above the map. A crumb whose payload is in the session cache shows that payload and does not rescan. The cache dies when the dialog closes.

Click a file: close the dialog. If the file's parent is not the active pane path, `paneStore.navigate` to the parent (that clears focus), then `setFocus` and `setSelection` to the file path. The grid already marks `row-focused` when that path is in `rows`. When the focused path appears in the loaded rows, scroll it into view the same way type-ahead does (`scrollToIndexes`). `Other` has no click.

Empty (`usage:done` with a tree and `total === 0`): "This folder is empty." A folder of only symlinks is this case.

`error` on `usage:done`: the error text, no rectangles.

`truncated`: one line, "Map is abbreviated. Open a folder for more detail."

`deniedCount > 0`: one line, "N folders could not be read." Do not dump the path list into the dialog.

## Tests

`go test` in `filesystem`:

- Files written under a temp tree sum to `Total`. A directory's own metadata size is not part of the sum.
- A symlink to a large file is not a node and does not add the target's size. A symlink to a directory is not walked.
- A file past `maxDepth` adds to the ancestor `Size`, and that ancestor has no `Kids`.
- A dotfile is included.
- Two children under 1% of the root become one `Other` whose size is their sum. A child at or above 1% stays.
- An unreadable subdirectory is on `denied`, and a readable sibling is still counted.
- Cancel before the walk finishes: done payload has `error` containing the cancel, and `tree` is nil.

Service test or the filesystem test above is enough for the walk. Additionally, a small service test that trash, an archive path, and a remote path return an error and do not emit `usage:done`.

Frontend: unit-test `layout.ts`. One child fills the box. Two equal children split the shorter side. A zero total yields no rects.

No Playwright spec. The walk is local and slow.

## Must not

- Read file contents. Size comes from `Lstat` and directory sums.
- Use `DiskUsage` as the treemap data. That is the volume. Leave the status bar on `DiskUsage`.
- Follow symlinks or descend into a vault.
- Add a treemap npm or Go dependency.
- Put the map in a third pane or replace the grid.
- Delete, trash, or move from a rectangle.
- Hand-edit `frontend/bindings/**`.
- Touch `document` or `window` from the new React code.
