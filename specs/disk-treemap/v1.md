# Spec: Disk usage treemap V1

Status: draft
Out of scope: remote trees, file delete from the map, a squarified layout library, replacing the file grid

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Current behavior

`filesystem.DiskUsage(path)` returns volume `Total`, `Free`, `Used` for the disk that contains `path` (`domain.DiskUsage`). The status bar shows free space for a local path (`StatusBar.tsx`). `DirChildSizes` / the folder-sizes action fills immediate child folder sizes on the grid. Neither is a treemap. There is no per-folder breakdown view.

## Desired

A view of one local folder: rectangles sized by byte size, like WinDirStat, for that folder only (not the whole disk unless the user opens the volume root).

`FileService.TreeUsage(jobID, root string, maxDepth int) error`

Walk like the size walk (skip symlink children, same as `filesystem/sizes.go`). Emit one `usage:chunk` when the walk finishes (not per file — a large tree must not stream one event per file):

```go
type UsageNode struct {
    Name  string `json:"name"`
    Path  string `json:"path"`
    Size  int64  `json:"size"`
    IsDir bool   `json:"isDir"`
    Kids  []UsageNode `json:"kids,omitempty"`
}
```

`maxDepth` default 4. Deeper files roll into their ancestor's `Size` without further `Kids`. Files under 1% of the root size collapse into a sibling named "Other" at that level so the payload stays small. Cap the JSON at 2MB; if it would exceed that, stop descending and set a `truncated` flag on `usage:done`.

`usage:done` carries `root`, `total`, `truncated`, `error`. `CancelJob` aborts the walk. Denied directories are skipped and named on `usage:done` as `denied []string` (same idea as `domain.DirSizes.Denied`).

Remote, archive, and trash roots return an error and emit nothing.

## UX

Toolbar button `data-testid="btn-treemap"` on a local folder, command palette id `treeUsage`. No default function key.

Opens a dialog (not a third pane) `data-testid="dialog-treemap"`. Layout is a squarified treemap implemented in the component (a few dozen lines: sort by size, slice the row). Rectangles show the name when the box is wide enough. Hover tooltip: name and byte size via MUI `Tooltip`. Click a directory rectangle to set it as the root and run `TreeUsage` again. Click a file to select that path in the active pane (close the dialog).

Color by top-level child, cycling a fixed palette of theme tokens. Do not color by file type in V1.

Empty folder: "This folder is empty."

## Tests

Walk a temp tree: sizes add up to the files written; a symlink child is not counted twice; depth past `maxDepth` still includes the bytes in the parent `Size`; cancel returns before `usage:done` with an error or a canceled done payload — pick one and test it (`error` on `usage:done` containing the cancel).

## Must not

- Read file contents. Size comes from `Lstat` / directory sums.
- Use `DiskUsage` as the treemap data. That is the volume, not the folder.
