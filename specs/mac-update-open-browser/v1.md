# Spec: macOS update check opens browser instead of self-installing V1

Status: draft
Out of scope: code-signing/notarizing the macOS build (the actual reason self-update is unsafe here), Sparkle-style delta updates, changing the Windows/Linux update flow at all

## Problem

`UpdateService.CheckAndInstall()` (`internal/service/update_service.go:46`) is a thin wrapper over `app.Updater.CheckAndInstall` (`wails/v3/pkg/updater`), which unconditionally opens the built-in update window, checks GitHub Releases, then on finding a newer version downloads it and stages a binary swap (`Restart` replaces the running `.app` bundle in place). That swap produces an **unsigned** bundle — there's no Apple Developer subscription behind this build — so Gatekeeper flags the replaced app as damaged/unverified on next launch. Self-update on macOS is actively harmful right now, not just unsupported.

`useUpdateActions.ts:17-27`'s `check()` is the only caller (wired to the single "Check for updates" button in `UpdatesSection.tsx:47-56`), on all three platforms alike.

## Fix

Branch by host OS, at the button's behavior, not by hiding the button. macOS keeps "Check for updates" working — it just doesn't try to self-install: it checks GitHub, and if newer, opens `ReleasesURL()` in the browser (already exists: `UpdateService.OpenReleasesPage`, `internal/service/update_service.go:54-56`) so the user grabs the `.dmg` by hand. Windows/Linux keep today's flow untouched (`app.Updater.CheckAndInstall`, built-in window, real self-update).

`app.Updater.Check(ctx)` (`wails/v3/pkg/updater/updater.go:201`) already exists and does exactly "ask GitHub, don't download" — returns `(*Release, error)`, `nil, nil` when up to date. This is a check-only call already used internally by `CheckAndInstall`; nothing new needed on the wails side.

### Backend

`internal/service/update_service.go` — new method next to `CheckAndInstall`:

```go
// CheckForUpdate checks GitHub Releases without downloading or installing.
// Returns the newer version string, or "" if already up to date.
func (s *UpdateService) CheckForUpdate() (string, error) {
    if s.app == nil {
        return "", fmt.Errorf("updater not ready")
    }
    rel, err := s.app.Updater.Check(context.Background())
    if err != nil {
        return "", err
    }
    if rel == nil {
        return "", nil
    }
    return rel.Version, nil
}
```

No macOS branching inside this method — it's a plain check, reusable on any platform. The macOS-vs-not decision belongs to the caller, because it's a policy choice ("don't self-install here"), not a fact about what `Check` returns.

Nothing changes in `CheckAndInstall` itself — Windows/Linux keep calling it exactly as today.

### Frontend

`frontend/src/features/updates/hooks/useUpdateActions.ts` — branch `check()` on `hostOS()` (`frontend/src/shared/lib/hostOS.ts`, already used elsewhere for platform-conditional UI, no new detection mechanism):

```ts
import { hostOS } from '../../../shared/lib/hostOS';

const check = useCallback(async () => {
  setBusy(true);
  try {
    if (hostOS() === 'darwin') {
      const version = await UpdateService.CheckForUpdate();
      if (version) {
        await UpdateService.OpenReleasesPage();
        show(`Update v${version} available — opened the releases page`, 'info');
      } else {
        show('Already up to date', 'info');
      }
    } else {
      await UpdateService.CheckAndInstall();
    }
    markChecked();
  } catch (e) {
    show(errMessage(e), 'error');
  } finally {
    setBusy(false);
  }
}, [markChecked, show]);
```

`UpdatesSection.tsx:62-64` caption — make it match what actually happens, conditioned the same way:

```tsx
<Typography variant="caption" color="text.secondary">
  {hostOS() === 'darwin'
    ? 'Checks GitHub and opens the release page in your browser — download the .dmg manually.'
    : 'Checks open the built-in update window (download, verify, restart to apply).'}
</Typography>
```

## Must not

- Hide/disable the "Check for updates" button on macOS — it still works, it just doesn't self-install. Don't make macOS users hunt for a different control.
- Touch `app.Updater.CheckAndInstall` or the Windows/Linux path — this is a macOS-only carve-out, not a rewrite of the update flow.
- Try to download/verify/stage the release ourselves on macOS "the safe way" — out of scope, the actual fix for self-update is code-signing + notarization, which needs the paid Apple Developer subscription this spec explicitly works around not having.
- Auto-open the browser without the user clicking "Check for updates" first — no surprise tab-opens; this stays an explicit, user-initiated action same as today's button.
- Guess the platform from `runtime.GOOS` on the frontend or duplicate `hostOS()`'s detection logic — one source of truth, already in the codebase.

## Done when

- [ ] `UpdateService.CheckForUpdate()` on a machine with a newer GitHub release → returns that version string, no download/window side effects
- [ ] same, already latest → returns `""`, no error

- [ ] macOS: clicking with no newer release → snack says up to date, no browser tab opens
- [ ] Windows/Linux: "Check for updates" behavior unchanged (built-in window, real self-update) — regression check, not new coverage
