# Spec: Bookmark tooltip does not cover the remove button V1

Status: implemented
Out of scope: bookmark storage, renaming bookmarks, a different dropdown, remote vs local grouping

Cursor: implement this spec only. Read `frontend/AGENTS.md` first. Layout only. No Go, no bindings.

## Problem

In the toolbar bookmarks dropdown (`BookmarksSelect`), each saved path row is a label plus a remove button (`CloseIcon`). The full path is a MUI `Tooltip` with `placement="right"` wrapped around the label `Typography` (`flex: 1`). The tooltip anchor is that wide flex box, so the popper opens on its right edge and paints over the X. The remove control cannot be clicked while the tip is open.

The shortened path (`shortenPath`) stays in the row. The tip is only there to show the full path.

## Layout

The tip shows `option.path` and does not intersect the remove button.

- Anchor the tooltip to the label text, not to the remove `IconButton` and not to the whole `<li>`.
- Place it above or below the row (`top` or `bottom`). `placement="right"` overlaps the button; do not use it.
- The remove button stays `flexShrink: 0` at the trailing edge (`bookmarkRemoveBtnSx`). Give the tooltip popper a width cap so a long path wraps or ellipsizes inside the tip (`maxWidth` around 360) instead of stretching across the button.
- Hovering the X does not need a tooltip. Clicking it still calls `removeBookmark` (`stopPropagation` stays, so the click does not navigate).
- If the tip is already open over the label, a click on the X still hits the button. Do not put the tooltip in a portal that covers the button.

Styles live in `frontend/src/widgets/toolbar/styles.ts`. Do not dump `sx` inline in `BookmarksSelect` beyond what is already there.

## Check

e2e, same harness as `e2e/specs/bookmarks.spec.ts`:

- Add the current path as a bookmark (the existing spec already does this).
- Open `input-bookmarks`.
- Hover the bookmark option’s label.
- The tooltip role is visible and its text is the full path.
- The remove button (`aria-label` starting with `remove-bookmark-`) has a bounding box that does not intersect the tooltip’s bounding box.
- Click that button. The option disappears. No extra dismiss step before the click.

## Must not

- Remove the full-path tooltip.
- Hide the X, or make the row navigate when the X is clicked.
- A custom tooltip component.

## Done when

Hovering a saved bookmark shows the full path, and the X is visible and clickable beside the tip.
