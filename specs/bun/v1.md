# Spec: Bun instead of npm V1

Status: draft
Out of scope: a Bun workspace, changing dependency ranges, running the Wails webview on Bun, deleting the npm/pnpm/yarn task variants in `build/Taskfile.yml`, the Go CI job

Cursor: implement this spec only. Read root `AGENTS.md` first. The tree is on npm today. This spec is the whole migration.

## Goal

Bun 1.4.2 is the package manager for three separate packages: the repo root (Husky), `frontend/`, and `e2e/`. Installs, scripts, and lockfiles do not go through `npm` or `npx`.

`build/Taskfile.yml` already has `install:frontend:deps:bun`, `frontend:run:bun`, and `frontend:dev:bun`. Leave those tasks, and the npm/pnpm/yarn siblings, as they are. They are the Wails template. This repo stops selecting npm.

## Lockfiles

Three lockfiles today, all tracked:

- `package-lock.json`
- `frontend/package-lock.json`
- `e2e/package-lock.json`

Replace each with a `bun.lock` in the same directory. Generate with Bun **1.4.2** (`bun install` in that directory). Delete the three `package-lock.json` files. Commit the three `bun.lock` files. Do not add `bun.lockb`.

Each `package.json` gains `"packageManager": "bun@1.4.2"` and nothing else. After `bun install`, diff `package.json`. If Bun rewrote dependency ranges, sorted the file, or changed anything besides `packageManager`, put those hunks back. Ranges stay what they are now (`frontend/package.json` still starts `@codemirror/commands` at `^6.10.4`).

`frontend/.oxfmtrc.json` `ignorePatterns` lists `package-lock.json`. Change that entry to `bun.lock`.

## Commands that must change

`bun test` is Bun's own test runner. Playwright is `bun run test`. Never `bun test` for e2e.

| Place | Today | After |
| --- | --- | --- |
| `Taskfile.yml` var `PACKAGE_MANAGER` | `default "npm"` | `default "bun"` |
| `Taskfile.yml` `frontend:lint` | `npm run lint`, `knip`, `format:check` | `bun run` the same three scripts. `dir: frontend` stays. |
| `Taskfile.yml` `check:build` | `npm run build --prefix frontend` | `bun --cwd frontend run build` |
| `Taskfile.yml` `test:e2e` | `npm test` | `bun run test` (`dir: e2e` stays) |
| Root `package.json` `knip` | `npm run knip --prefix frontend` | `bun --cwd frontend run knip` |
| Root `lint-staged` | `npm run lint --prefix frontend`, `npm run format --prefix frontend` | `bun --cwd frontend run lint`, `bun --cwd frontend run format` |
| `e2e/global-setup.ts` `buildApp` | `execSync("npm run build", { cwd: frontend })` | `execSync("bun run build", …)` |
| `e2e/scripts/prepare-and-start.sh` | `npx --yes tsx ./global-setup.ts` | `bun ./global-setup.ts` |

`wails3 dev` / `wails3 build` install and run the frontend through `PACKAGE_MANAGER`. Default `bun` is what makes those use the existing `*:bun` tasks. The three Taskfile rows above do **not** read `PACKAGE_MANAGER`. Change them explicitly or `task check` still calls npm.

### Direct-run guard in global setup

`e2e/global-setup.ts` ends with `if (require.main === module)`. Playwright imports the file and calls the default export. The shell script runs the file as a program. `bun ./global-setup.ts` does not set `require.main`. Replace the guard with:

```ts
if (process.argv[1]?.endsWith("global-setup.ts")) {
  globalSetup().catch((err) => {
    console.error(err);
    process.exit(1);
  });
}
```

Playwright's `argv[1]` is the Playwright CLI, so the import path does not run `globalSetup` twice.

## CI

Frontend job in `.github/workflows/ci.yml` only. The Go job stays.

Remove `actions/setup-node@v6` from that job. Use:

```yaml
- uses: oven-sh/setup-bun@v2
  with:
    bun-version: 1.4.2
- run: bun install --frozen-lockfile
- run: bun run lint
- run: bun run knip
- run: bun run format:check
- run: bun run build
```

`working-directory: frontend` stays. `--frozen-lockfile` is the `npm ci` equivalent: fail if `bun.lock` does not match `package.json`.

## Leave alone

- `build/Taskfile.yml` npm, pnpm, yarn, and bun task bodies.
- `frontend/src/widgets/port-killer/helpers.ts` comment about node/npm process names. That is a process label, not the package manager.
- Dependency version ranges.
- `node_modules/` (gitignored). Do not commit it.

## Check

- `bun install --frozen-lockfile` exits 0 in `frontend/`.
- `bun --cwd frontend run build` exits 0 (the compile gate `check:build` uses).
- `rg` for `npm ` and `npx ` in `*.yml`, `*.md`, `*.sh`, `*.ts`, and `package.json` has no install or script invocation outside `build/Taskfile.yml` and this spec.
- `package-lock.json` is gone at the root, `frontend/`, and `e2e/`. `bun.lock` exists in all three.
- `git diff` on the three `package.json` files shows only `packageManager` plus the script/lint-staged lines in the table above.

`bun run lint` in `frontend/` runs `tsc --noEmit && oxlint`. If oxlint fails on rules that already fail under `./node_modules/.bin/oxlint` before this change, that failure is pre-existing. Do not "fix" those components in this spec. Do confirm `bun run lint` invokes that same script, not a different binary.

## Must not

- `bun test` as the e2e task.
- A second package manager left as the default (`PACKAGE_MANAGER` still `"npm"`).
- Editing `frontend/bindings/**`.
- Deleting the npm task variants in `build/Taskfile.yml`.

## Done when

A clean checkout can `bun install` at the root, in `frontend/`, and in `e2e/`, and `task check:build` / the frontend CI job do not call npm.
