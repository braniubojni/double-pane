# Spec: Folder / file password vault V1

Status: implemented
Out of scope: FUSE / macFUSE / FUSE-T mounts, encrypted DMG / sparsebundle, zip/7z password archives, VeraCrypt/Cryptomator interop, remote vaults (`ssh://` `smb://` `mega://`), Keychain password storage, recovery-key UX, filename-structure hiding beyond per-entry name encryption, Open-With temp decrypt + re-encrypt on close, Time Machine exclude UI, multi-vault concurrent write from two app instances

Cursor: implement this spec only. Do not invent FUSE mounts or wrap `hdiutil`. Read root `AGENTS.md`, `internal/AGENTS.md`, `frontend/AGENTS.md` first. Questions ≠ work does not apply — this file is the implementation brief.

## Goal

User can lock a **local folder** or a **local file** with a password inside Double Pane.

- Locked = ciphertext on disk. Finder and other apps see only encrypted blobs. Nothing stays mounted.
- Unlocked = session in this process only. Pane lists plaintext names, copy/move/open-in-app stream decrypt/encrypt. Leave the vault in **both** panes → auto-lock. Quit app → lock. Optional idle timeout.
- Large files (1 GB+) never go through zip/unzip or a single in-memory buffer. Encrypt/decrypt is streaming, per file.

This is the point vs zip (rewrite whole archive) and vs encrypted DMG (volume stays mounted after you leave the folder).

## Why not wrap existing tools

| Option | Why V1 does not use it |
| ------ | ---------------------- |
| Password zip | Rewrites the whole archive on any change. Nightmare past ~1 GB. |
| Encrypted DMG / sparsebundle | Works, but the volume stays mounted in Finder until eject. That is the reported bug. |
| Cryptomator / gocryptfs / VeraCrypt | Good standalone apps. They still mount a volume. Do not shell out to them. |
| `EncryptedKV` in SQLite | Fine for SSH key blobs, not for GB files. |

V1 is a first-party vault the file manager understands, so lock-on-leave is a navigation event, not a mount.

## Threat model (honest)

Protects against: sibling / coworker glancing at Finder, stolen disk without the password, Time Machine / cloud sync of the vault folder (they sync ciphertext).

Does **not** protect against: malware in the same user session while the vault is unlocked, memory dump of this process, evil maid with the password, or someone who already has the unlocked pane open.

Password is never written to `settings.json`, SQLite, or Keychain in V1. Session key lives in process memory only.

## On-disk format

Vault root is a normal directory containing:

```text
<vault>/
  .dpvault/
    manifest.json          # unencrypted: version, kdf, salts, wrapped DEK
    d/                     # ciphertext objects, one file per plaintext file
```

`manifest.json` example:

```json
{
  "version": 1,
  "kdf": "argon2id",
  "argon2": { "time": 3, "memoryKiB": 65536, "threads": 4 },
  "salt": "<base64 16 bytes>",
  "dekWrapNonce": "<base64 12 bytes>",
  "dekWrapped": "<base64 AES-256-GCM(KEK, DEK || vaultID)>",
  "vaultID": "<hex 16 bytes>"
}
```

- Password → Argon2id (`golang.org/x/crypto/argon2`) → 32-byte KEK.
- Random 32-byte DEK generated at create time, wrapped with KEK (AES-256-GCM).
- Changing password in V2 would re-wrap DEK; V1 has no change-password UI (Must not).

Each plaintext file maps to one object:

```text
.dpvault/d/<vaultID-short>-<contentID>.dpobj
```

Object layout (binary, little-endian):

```text
magic[8] = "DPV1OBJ\n"
nameNonce[12]
nameCT[len][16]          # AES-GCM of UTF-8 relative path (posix, `/` separators)
origSize[8]
mtimeUnix[8]
chunkSize[4]             # 1 MiB
chunkCount[4]
for each chunk:
  chunkNonce[12]
  chunkCT[n][16]         # AES-GCM of up to chunkSize plaintext
```

AAD for every GCM seal = `vaultID || objectID || chunkIndex` so chunks cannot be swapped.

Directories are not separate objects. A directory exists if any stored relative path has that prefix. `Mkdir` writes a zero-byte object whose name ends with `/`.

Single-file vault (lock one file, not a folder): sibling file `<name>.dpenc` — same object layout, no `.dpvault/` directory. Manifest fields are a 512-byte JSON header before `magic` (length-prefixed uint32 + JSON + padding to 512). Same KDF.

Detect:
- Folder vault: `IsDir && file exists(<path>/.dpvault/manifest.json)`
- File vault: ext `.dpenc` or header magic after the 512-byte prefix

## Entry

File menu + context menu (local paths only):

- **Lock with password…** — enabled when selection is one local folder that is **not** already a vault, or one local regular file that is **not** `.dpenc`. Disabled on multi-select, remotes, archives (`FileService.IsArchivePath`), `trash://`, vault internals (any path under `.dpvault/`).
- **Unlock…** — enabled when selection/cwd is a locked vault (folder or `.dpenc`) and that vault is not in the session map.
- **Lock now** — enabled when the focused path is inside an unlocked vault.
- **Remove password…** — enabled when focused path is an unlocked vault root (folder) or an unlocked `.dpenc`. Decrypts everything back to plaintext, deletes vault metadata. Confirm dialog.

Disabled while a vault job (create / remove / lock-file) is running for that path.

Shortcut: none in V1 (no `shortcuts.json` change). Command palette can list the four actions if the palette already enumerates File-menu items — do not special-case.

## Create folder vault

Dialog (lazy MUI, ~100–150 lines):

- Path (read-only, the selected folder)
- Password
- Confirm password
- Hint (optional, stored **plaintext** in `manifest.json` as `hint` — label the field "stored next to the vault, not secret")
- Buttons: Cancel, Lock

Validation:

- Password min 8 chars. No max composition rules.
- Passwords must match.
- Folder must be writable, not a vault, not inside another vault.
- Refuse if folder is the current user's home, `/`, or a volume root (`internal/volumes`). Too easy to brick.

Job (background, same pattern as copy / duplicate-finder):

1. Write `.dpvault/manifest.json` + empty `d/` first (crash-safe marker).
2. Walk folder (skip `.dpvault` itself). Hidden files included always — vault is all-or-nothing.
3. For each file: stream-encrypt to a temp name in `d/` then rename into place. Then `os.Remove` the plaintext. Never `os.ReadFile` the whole file.
4. For each now-empty plaintext dir: `os.Remove`. Leave the vault root.
5. Progress events: `filesDone/filesTotal`, `bytesDone/bytesTotal`, current relative path.
6. Fatal error: stop, leave already-encrypted files as-is, keep plaintext that was not yet converted, surface path + error. User can retry "Lock with password" on the same folder — skip files that already have objects (match by relative path after decrypt of names requires password; on retry the folder is a half-vault). Simpler retry rule: if manifest exists and DEK unwrap works, continue walking plaintext files **outside** `.dpvault/` only.

After success: if a pane was inside that folder, treat it as unlocked and refresh list (plaintext names).

Disk space: need ~1× source size free on the same volume during convert (ciphertext written before plaintext deleted). Pre-check with `DiskUsage` / volume free space; abort before writing if free < source size + 64 MiB.

## Unlock

Dialog: password (+ show stored hint if present). Wrong password → wrap error `invalid password` (GCM open fail on wrapped DEK). Do not distinguish missing manifest vs bad password beyond "not a vault" when marker absent.

On success: insert `session[absPath] = {dek, unlockedAt}` in process memory. `FileService.List` on that path and descendants returns decrypted names + `origSize` + `mtime`. `.dpvault` is hidden from the list even when Show hidden is on.

Unlocking `.dpenc`: session key keyed by the file's abs path. List of the parent folder shows the original name without `.dpenc` while unlocked? **No.** Parent list always shows the `.dpenc` filename. Double-click / Enter on an unlocked `.dpenc` in V1 does not "enter" it (it is a file). Copy/move out decrypts to destination name minus `.dpenc`.

## Lock now / auto-lock

`Lock(vaultRoot)` drops the session entry and overwrites the DEK bytes (zero the slice). Next `List` of that path returns a **single synthetic row** if listing the parent: the vault folder with `IsVault: true, VaultLocked: true`. Entering it without session → frontend opens Unlock dialog instead of listing ciphertext.

Auto-lock triggers:

1. After any pane path change: if a session vault root is no longer a prefix of **either** pane path, lock it.
2. App shutdown (`app.OnShutdown` next to existing teardown).
3. Idle: if `Settings.VaultIdleLockMinutes > 0` (default **5**) and no vault I/O / list / path change for that many minutes, lock all sessions. `0` = off.

Do not watch Finder. There is no mount.

## Browse + mutate while unlocked

All through existing `FileService` methods. Detect vault prefix via session map.

| Op | Behavior |
| -- | -------- |
| List | Decrypt names. Filter out `.dpvault`. |
| Copy vault → outside | Stream decrypt to dest. Progress like normal copy. |
| Copy outside → vault | Stream encrypt into new object. |
| Copy vault → vault (same) | Re-encrypt under dest name (do not copy ciphertext blindly — names/AAD differ). |
| Move inside vault | Rename relative path in object header only when dest is same vault (rewrite header, same chunks). If dest leaves the vault, decrypt-copy + delete object. |
| Delete | Delete object file. OS trash: decrypt-copy into trash then delete object (so restore is plaintext). If decrypt-to-trash is too much for V1, **hard-delete the object and skip OS trash** with confirm text "Locked files cannot go to Trash. Delete permanently?" Prefer the confirm + permanent delete in V1 (less code, no plaintext residue in Trash). |
| Rename | Rewrite name field; same chunks. |
| Mkdir | Zero-byte directory object. |
| Open in built-in editor | Stream decrypt to a temp file under config dir `vault-open/` with random name. On editor close, if mtime/size changed, re-encrypt and replace object; always `os.Remove` temp. If editor is read-only preview, skip re-encrypt. |
| Open with OS app | V1: disabled for vault items. Snackbar: "Unlock and copy out, or use the built-in editor." |

Jobs must hold the session DEK for the duration. If auto-lock fires mid-job, job finishes then lock (do not yank DEK under an active encrypt). Track `inFlight` per vault.

## Remove password

Unlock first. Confirm. Job: walk objects, stream decrypt to original relative paths **beside** `.dpvault`, then `os.RemoveAll(.dpvault)`. Fail mid-way = mixed tree; retry continues for remaining objects.

`.dpenc` remove: decrypt to `<name>` without suffix, delete `.dpenc`.

## Backend contract

New package `internal/vault` (pure, no Wails). Thin methods on `FileService`.

```go
type VaultInfo struct {
    Root     string
    Locked   bool
    IsFile   bool // .dpenc
    Hint     string
    Version  int

func Detect(path string) (VaultInfo, bool)

func CreateFileVault(ctx context.Context, file, password, hint string, ev func(VaultJobEvent)) error

func RemoveProtection(ctx context.Context, path, password string, ev func(VaultJobEvent)) error

```

`FileService` Wails surface (exact names — bindings regen):

```go
func (s *FileService) DetectVault(path string) (domain.VaultInfo, error)
func (s *FileService) StartCreateVault(path, password, hint string) (jobID string, err error)

func (s *FileService) ListUnlockedVaults() []domain.VaultInfo
```

Password arguments cross Wails IPC in memory for that call only. Do not log them. Do not put them on job events.

`domain.FileInfo` gains:

```go
IsVault       bool
VaultLocked   bool
VaultFile     bool // .dpenc
```

`List` fills these so the grid can show a lock icon without a second round-trip.

`Settings` gains `VaultIdleLockMinutes int` default `5`. `0` disables. Settings UI: number field under a "Vaults" group.

Job events reuse the existing job/progress channel pattern (copy / duplicates). Payload:

```go
type VaultJobEvent struct {
    JobID      string
    Kind       string // create | create-file | remove
    Path       string
    FilesDone  int
    FilesTotal int
    BytesDone  int64
    BytesTotal int64
    Current    string
    Err        string
    Done       bool
}
```

## UI

- Lock icon on vault rows (`FilePane` name cell). Closed lock if `VaultLocked`, open lock if session unlocked.
- Status-bar chip while any vault session is open: `Vault · N open` — click → Lock all.
- Dialogs: `frontend/src/widgets/vault/` (`LockDialog.tsx`, `UnlockDialog.tsx`, `RemoveDialog.tsx`) lazy-loaded like Settings.
- Context menu + File menu wiring in `frontend/src/widgets/menu/`.
- Progress: existing job UI / status bar, not a new framework.

Copy/move of a **locked** vault folder copies the ciphertext directory as a normal folder (so the vault remains portable). Do not try to decrypt.

## Crypto implementation notes

- `crypto/aes`, `crypto/cipher` GCM, `crypto/rand`, `golang.org/x/crypto/argon2`.
- Chunk size 1 MiB. Tests may use 64 KiB via an unexported test hook, not a user setting.
- Never `ioutil.ReadFile` / `os.ReadFile` on payload.
- Zero DEK/KEK slices on lock with a small `vault.Wipe(b []byte)` helper.
- Argon2 memory 64 MiB is acceptable on the M-series machines this app targets. Do not raise without a setting.

## Must not

- Mount anything (`hdiutil`, `diskutil`, FUSE, WebDAV localhost).
- Shell out to Cryptomator, VeraCrypt, gpg, zip `-e`.
- Store the password or DEK in settings, SQLite, or Keychain.
- Encrypt remotes, archives, or trash in V1.
- Change password / recovery key UI.
- Decrypt a whole vault to a sibling plaintext folder "for convenience" on unlock.
- Commit generated `frontend/bindings/**`.
- Add a heavy crypto framework (age, minio sio, cryptomator lib). Stdlib + `x/crypto/argon2` only.
- Log paths together with "password accepted" at debug that could leak timing of specific vaults in shared logs — plain `unlock ok` without path is fine.
