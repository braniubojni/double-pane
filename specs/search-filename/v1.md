# Spec: Search by file name V1

Status: draft
Out of scope: content search changes, smart folders, size/date filters (those are separate specs), fuzzy ranking beyond the existing `RankSearchHits`

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Current behavior

Find-in-files (`FileService.StartSearch`) has two modes:

- `domain.SearchModeContent` (`"content"`) — text inside files (`filesystem.SearchContent`). UI label "Text in files".
- `domain.SearchModeFolders` (`"folders"`) — directory names only. `SearchFolders` skips non-directories (`if !entry.IsDir() { continue }`) and skips symlinks. UI label "Folder names". Placeholder "Folder name…".

`SearchPrefs.Mode` is persisted (`settings_service.go` accepts only those two strings). Go-to (`SearchTree`) matches any name, but that is a different dialog.

There is no file-name mode. A query for `readme` in folder mode does not return `readme.md`.

## Desired

Third mode `domain.SearchModeFiles` (`"files"`).

`filesystem.SearchFiles` walks like `SearchFolders` (same limit default 500, same `maxFolderSearchVisits`, same include/exclude via `NewPathFilter`, same hidden and symlink skips) but emits **files**, not directories. Match is case-insensitive substring on the basename, same as folder mode's `strings.Contains` on the lowercased name. Empty query emits nothing (do not list the whole tree).

Remote: `FileService.searchFoldersRemote` has the same folder-only filter. Add `searchFilesRemote` with the same walk (`walkRemote`) and emit file hits. MEGA is allowed for this mode (content search stays blocked on MEGA; name search does not read file bytes).

`StartSearch` mode `"files"` streams `search:hit` with `Mode: "files"` and `Folder` set to the `domain.SearchHit` (reuse the folder payload; the hit's `IsDir` is false). Do not add a third payload field.

`SearchPrefs` and the settings normalizer accept `"files"`. Unknown mode still falls back to content.

## UX

`frontend/src/widgets/search/types.ts` `SearchMode = 'content' | 'folders' | 'files'`.

Radio in `SearchForm.tsx`, `data-testid="search-mode"`, third option "File names". Placeholder "File name…". Replace stays disabled for this mode, same as folders (`prefs.mode === 'folders'` today — treat both non-content modes the same).

`useSearchSession.ts` uses the folder limit (500) for this mode, not the content limit (2000).

## Tests

- temp tree with `a/readme.md` and `a/sub/` and query `readme` → one hit, the file, not the directory
- folder mode still does not return `readme.md`
- include `*.md` keeps the md file; exclude drops it
- symlink file is skipped

## Must not

- Match on the relative path. Basename only, so a query of `src` does not hit `src/main.go` unless the file itself is named with `src`.
- Read file bytes in this mode.
