# Spec: Remote reconnect and pane connection status V1

Status: draft
Out of scope: resuming a half-written SFTP upload after reconnect (`specs/sftp-transfer-control/v1.md` says a dead connection fails the job), MEGA session refresh, changing bookmark paths

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Current behavior

`ConnectionService.ListSessions` returns `domain.ActiveSession` (`Key`, `Protocol`, `User`, `Host`, `Port`, `RootPath`) for live SSH/SMB/MEGA maps. The pane shows a cloud icon on remote tabs (`PaneTabs.tsx`) and otherwise treats a dead session as a failed `ListDir` (the grid error state). Nothing dials again. `Disconnect` drops the session when the user asks. Passwords are not stored (see `specs/remote-keychain/v1.md`); a reconnect that needs a password uses the existing password dialog.

SSH `Manager` has no keepalive read. A dropped TCP connection surfaces on the next SFTP call.

## Desired

When `ListDir` (or read/write) fails because the session is gone, try one reconnect, then show status.

Detect "session gone": SSH client `Wait` / closed conn, SMB session error that is not an auth rejection (`IsSMBAuthError` stays a password prompt, not a reconnect loop), MEGA not included — MEGA failures stay errors.

Reconnect:

- One attempt per failure, not a timer loop.
- Same `remote.Spec` as the live session. Password: the in-memory password from the original `Connect` if the process still has it; else keychain if that spec is implemented; else the password dialog (`open_password`) and do not auto-retry with an empty secret if the first connect needed one.
- Keys/agent: same `IdentityFiles` as the profile.
- Success: retry the `ListDir` once. Failure: surface the error as today.

Status on each pane whose path is remote:

- `connected` — last list succeeded
- `reconnecting` — the one retry is in flight
- `disconnected` — the retry failed or `Disconnect` was called while the pane still shows that path

This is derived from the list query (`useDirListing`) plus a small Zustand flag for "reconnect in flight". Do not poll with `useEffect`.

UI: a caption on the pane path bar, `data-testid="pane-conn-status"`, text "Connected" / "Reconnecting…" / "Disconnected". Disconnected offers "Reconnect" which calls `ConnectProfile` or `ConnectSpec` for that session key. The cloud icon on the tab stays; color it with the status (default, warning, error) via the MUI palette, not a new icon set.

`ListSessions` is the source for "is there a live map entry". After a failed reconnect the map entry is absent, so status is disconnected even if the path string is still `ssh://`.

## Tests

Inject a backend that fails once with a closed-connection error and then lists: the service retries once and returns the list. A second distinct failure does not retry again inside the same call. `IsSMBAuthError` does not retry.

## Must not

- A background goroutine that dials every N seconds.
- Reconnect MEGA inside this spec.
- Hide the grid error text when disconnected; the caption and the error can both show.
