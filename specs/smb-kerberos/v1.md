# Spec: SMB Kerberos ticket auth V1

Status: draft
Out of scope: joining a domain, creating keytabs in the app, NTLM removal, SMB over QUIC

Cursor: implement this spec only. Read `internal/AGENTS.md` first. NTLM stays the fallback.

## Current behavior

`SMBManager.Connect` (`internal/remote/smb.go`) dials TCP and authenticates with `smb2.NTLMInitiator` from `github.com/cloudsoda/go-smb2`. The comment on `Connect` says NTLM. `ntlmAttempts` tries the resolved user, then variants. Empty user becomes the OS login name, not Guest. `ConnectionProfile.Domain` is the NTLM domain. The add-SMB dialog collects host, user, domain, port, password (`SMBConnectFields`). `IsSMBAuthError` detects a failed NTLM/guest logon.

There is no Kerberos or ticket path. A machine that already has a TGT still has to type an NTLM password.

## Desired

On connect, if the user asks for Kerberos, try the current user's ticket cache first. If that fails or there is no ticket, return an auth error the dialog can show. Do not silently fall through to NTLM on a Kerberos attempt: a bad ticket should not send the NTLM password to the server. NTLM remains a separate attempt when the user did not pick Kerberos (today's path).

`domain.ConnectionProfile` gains `Auth string` JSON `auth`: `""` or `"ntlm"` (default, current) or `"kerberos"`. Saved profiles remember the choice. Password may be empty for Kerberos.

`SMBManager.Connect` gains the auth choice (argument or a field on `remote.Spec` — `Spec` already has `Domain` and is what `ParseLocation` fills). Kerberos uses the process environment's default ccache (`KRB5CCNAME`, else the OS default). Do not read `/etc/krb5.keytab`. Do not prompt for a principal other than `user@realm` derived from the profile user and domain (domain is the realm when auth is kerberos).

Library: stay on `cloudsoda/go-smb2`. Its session takes an `Initiator`. NTLM uses `NTLMInitiator`. Kerberos needs an initiator that speaks SPNEGO/GSSAPI with the ccache. If this version of go-smb2 cannot accept that, stop and report it — do not shell out to `smbclient`, and do not add a second SMB stack. A new dependency is allowed only for the ticket (`gokrb5` or whatever already matches go-smb2's initiator) and only after the initiator interface is confirmed in the module.

## UX

SMB dialog: checkbox "Use Kerberos ticket" `data-testid="smb-kerberos"`. When set, password is optional and the helper text says the OS ticket cache is used. Domain is labeled realm. Connect error text distinguishes "no ticket" from "NTLM rejected".

## Tests

`TestNTLMAttemptsOrder` stays. Add a test that auth `kerberos` does not call `NTLMInitiator` (inject the initiator factory, or assert the spec flag skips `ntlmAttempts`). A live KDC test is not required.

## Must not

- Change guest/empty-user NTLM behavior when the checkbox is off.
- Store a ticket or keytab in SQLite.
