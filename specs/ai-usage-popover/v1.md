# Spec: AI usage popover has no scrollbar V1

Status: draft
Out of scope: new providers, changing quota math, moving this UI to the status bar, a settings page for AI usage

Cursor: implement this spec only. Read `frontend/AGENTS.md` first. CSS and layout only. No Go, no bindings.

## Problem

The toolbar popover (`frontend/src/widgets/ai-usage/`) scrolls. The user wants no scrollbar on it, including when a provider row is expanded.

The scroll comes from:

- `paperSx` in `styles.ts`: `maxHeight: min(560px, calc(100vh - 48px))` and `overflow: hidden`
- `listSx`: `overflow: auto` and `flex: 1 1 auto` / `minHeight: 0` (that pair is what creates the scrollport)
- `AIUsageMenu` puts that paper on MUI `Popover`

There are three providers (Claude, Grok, Cursor). Collapsed, they fit. Expanded limits and detail lines are what overflow the 560px cap.

## Layout

The paper sizes to its content. Nothing inside it scrolls.

- Remove `maxHeight` from `paperSx`.
- Remove `overflow: auto` from `listSx`. The list is a normal block (`overflow: visible`, no `flex: 1`, no `minHeight: 0`).
- Paper: `height: auto`, `overflow: visible`. Keep `width: 340`, `maxWidth: calc(100vw - 32px)`, `mt: 0.5`, radius, shadow.
- `contentSx`: drop the flex-column scroll setup if the column is only there to feed the scrollport. Stack header, rows, and the actions row in document flow.
- `disableScrollLock` on the Popover stays. The file list behind the popover must not freeze.
- Do not add `overflow: auto` or `scroll` on the paper, the list, a row, or a limit block. `overflow: hidden` on a row is OK only to ellipsize one line of text, and that line must not be a scrollport (`white-space: nowrap` + ellipsis, no scrollbar).

If MUI's Popover paper still clips, override it in `slotProps.paper.sx`. The override lives in `styles.ts`, not an inline dump in the component.

### Short windows

"No scrollbar" still holds when the window is short. Do not bring the scrollport back as a fallback.

- Tighten only if the expanded popover would extend past the bottom of the window: use the existing small type scale, and keep one limit block per provider (label, percent, reset, details). Do not invent a second view.
- Anchor stays bottom-right of the toolbar button (`AIUsageMenu`). If the expanded paper would cover the button, that is fine. If it would go off the top of the screen, leave it; do not add a scroll.
- Three providers expanded must be fully visible on a 800px-tall window without a scrollbar. If they are not, reduce vertical padding in `styles.ts` until they are. Do not drop data to make them fit.

## Components

Keep `AIUsageMenu`, `AIUsagePanel`, `AIUsageRow`, `helpers.ts`. Do not merge them into one file. No `useEffect`. Expanded row id stays in `useState` as it is now.

## Check

e2e is the check that can fail in CI. In `e2e/specs/` (follow `e2e/AGENTS.md`), open `btn-ai-usage`, expand every row that has `canExpand`, then assert the popover paper (`popover-ai-usage`) has `scrollHeight <= clientHeight + 1` and computed `overflow-y` is not `auto` or `scroll`. The same for the list element.

If a provider is not installed, the row is short. The test still expands whatever can expand, and still asserts no scrollport.

Also look at the running app: open the popover, expand each row, confirm the Refresh row is visible and there is no scrollbar. A screenshot of the closed toolbar is not the check.

## Must not

- `maxHeight` plus `overflow: auto` "just in case".
- A nested menu or a dialog.
- Backend changes.

## Done when

Expanded popover shows every provider, its limits, the Refresh button, and no scrollbar on the paper or the list.
