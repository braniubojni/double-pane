# Spec: Search inside archives V1

Status: draft
Out of scope: remote archives, writing matches back into the archive (replace stays disabled), nested archives (an archive member that is itself an archive), password prompting inside the walk (use the password already stored for that archive, else skip protected members)

Cursor: implement this spec only. Read `internal/AGENTS.md` and `frontend/AGENTS.md` first.

## Current behavior

`FileService.StartSearch` returns `search is not available inside archives yet` when `filesystem.IsArchivePath(root)` (`file_service.go`). The pane can list a local archive: path is the archive file plus inner members (`archive_browse.go`, `SplitArchivePath`). `ReadArchiveTextFile(archive, inner, password)` reads one member as text. `ErrArchiveReadOnly` blocks writes. `FileService.Archive` / `Extract` are local only.

Content and folder search both refuse the archive root, so the user cannot find a file inside a zip they are browsing.

## Desired

When `root` is a local archive path (the archive itself or a directory member inside it), `StartSearch` walks members instead of the filesystem.

- List members with the existing archive listing (the same source `ListDir` uses for an archive path). Do not extract to disk.
- Folder mode (`SearchModeFolders`): member directories whose basename contains the query.
- File-name mode, if `specs/search-filename/v1.md` is implemented: member files. If that mode does not exist yet, this spec does not add it.
- Content mode: for each file member under the size cap `SearchContent` already uses, read text via `ReadArchiveTextFile`. Password is `FileService`'s stored archive password (`archivePw`) when the user unlocked that archive; otherwise a member that needs a password is `search:denied`, and the walk continues.
- Include/exclude globs match the member's slash-separated path inside the archive.
- Symlink members: skip, same as the filesystem walk.
- Hits use the pane path form (`archive file` + inner path) so opening a hit uses the existing archive browse / editor read.

`limit`, `search:hit`, `search:denied`, `search:done` stay the same events.

Replace and replace-all stay disabled while the root is an archive (`ErrArchiveReadOnly`). The dialog's replace toggle is disabled, same as folder mode.

Remote `ssh://` / `smb://` / `mega://` archives still return the current "not available" error. Extract-to-temp-then-search is not this spec.

## Tests

Temp zip with `docs/readme.txt` containing `needle`, plus `docs/other.txt`:

- content query `needle` → one hit, path is inside the archive, line 1
- folder query `docs` → the directory member
- include `*.md` → zero hits
- a second zip nested as a member is not opened

## Must not

- `Extract` into a temp dir to search.
- Enable replace inside the archive.
